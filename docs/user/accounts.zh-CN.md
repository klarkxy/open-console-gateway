# 账号

**新增账号** 先区分已有连接与新服务。已有连接与 **供应商** 页使用同一套连接投影：只有至少还有一张账号的内置供应商，以及已保存的用户定义供应商（有无 Key 都列出）。删掉某个内置供应商的最后一张账号后，它会离开已有连接，回到新服务里的内置模板。选择已有连接会沿用其已保存的地址、协议和模型，只添加另一把 Key。选择新服务，再浏览未使用的内置模板、Plan/API 预设、Custom API 或平台站点。保存预设会同时创建供应商和首个账号。**供应商 → 添加供应商** 打开同一套选择器。从 **新增账号** 保存预设时，使用与 **供应商** 页相同的 onboarding commit。填写 Key 前始终可查看连接摘要，地区和套餐变体使用紧凑选择器。Key 由账号服务保存；你可以在本页添加，也可以在供应商详情里用 **添加 Key**。

供应商选项严格按 V4 目的地与目录投影返回的顺序投影，选择器、筛选、弹窗与缓存都使用 `provider_id`。成功返回空目录就保持为空；目录加载失败时只保留 OpenCode Go 创建表单，既有 Zen Free 单例仍可展示，其余内置、Custom 与用户定义入口全部失败关闭。名称、Plan/API 分组、创建状态与表单字段都来自目录行。密封供应商的第一张就绪账号保存后，面板先读取该供应商现有 Contract 的目录刷新能力，再决定是否刷新；追加第二把 Key 不重复刷新。能力查询或刷新失败不会回滚已经保存的账号，可到 **供应商 → 刷新模型目录** 重试。

**已启用** 表示这张卡可以进入路由。新建就绪 Key 账号（含 Custom API 与用户定义供应商）默认启用。测试连接不会改变开关。已经开启或关闭的账号保持原状态。测试结果保留在测试弹窗中。用户定义供应商没有建模订阅周期，包括从 Plan 预设创建的供应商：其账号不显示推算的购买日期、到期倒计时或到期提醒。既有存储中的购买日期锚点保留兼容，但不作为已经确认的计费事实展示。

账号使用与创建时相同的表单编辑。就绪且可路由的卡片只显示已启用、已禁用、冷却或不可用。卡片上的关系来自身份投影：声明关系不是已验证钱包；动态或 Custom 的日期保持未知，除非本来就存有真实的购买日期。

就绪的 Key 卡片可从溢出菜单 **轮换 Key**、**添加 Key** 和 **编辑绑定**。轮换只替换本机此后请求使用的 Key（凭据 id 不变，版本号递增），是本地替换：不会撤销供应商侧的原凭据，仍由你自行管理。**添加 Key** 在同一身份下再创建一把推理 Key，默认使用该卡片的连接。额度默认独立；只有你明确选择与同一身份下某把已有推理 Key 共享时才会共享，不会因为同属一个身份而自动共享。保存后，卡片按已存储的额度池显示实际共享关系（能确定时会写出共享的那把 Key）。同一身份上的第三把 Key 若有自己的池或没有池，仍是独立额度。Custom API、Zen Free、CPA、无鉴权和观察者凭据不提供添加 Key（Custom API 仍走账号专用编辑）。若创建没有得到确定结果，表单会锁定已提交的内容和操作：用相同内容重试，或取消；不要改内容后再提交（可能产生重复 Key）。

编辑绑定可改该凭据绑定的启用状态、模型范围（全部模型，或仅你列出的准确名称），以及——仅在你改动时——目标同意：允许此 Key 发往哪些已配置端点（协议和 URL）。已保存的目标是当时的事实；供应商地址日后更改时，仍显示已保存的 Origin，该端点保持未勾选，除非你明确允许新目标。只改范围或启用时不会改目标。两个目标列表都清空即撤销。没有 URL 的官方锁定端点保持官方目标，不会编造 Origin 字符串。绑定禁用显示在该卡片上，不会拨动账号启用开关。Zen Free、CPA、无鉴权和观察者凭据不提供轮换或绑定。一个身份可以持有多把 Key；每张卡片只用 `legacy` 账号 id 与自己匹配的那份凭据。

账号视图是租户名单。Provider 与 Plan 是同一个产品身份（只有 `provider_id`）；每张账号卡归属一个 Provider，并在该 Provider 需要时绑定一份凭据。额度权威随 Provider 而异：OpenCode Go 按账号 / Key 统计，Zen
Free 按出口 IP 共享额度与冷却，Custom API 不做供应商额度核算。所有卡片共享一份可手动持久化的全局顺序；请求先经过能力过滤，严格优先级、全局粘性和轮询再复用这份顺序。不存在按模型划分的额度池。

**账号** 负责身份、账号 **Key**、验证、启用状态、卡片顺序、托管注册，以及可用的账号用量
/ 冷却状态。本地目录、协议探测、按模型协议覆盖、用户定义供应商的 Endpoint/协议/映射，以及范围内价格都在
**供应商** 页。用户定义供应商账号只保存 Key（鉴权需要时）、备注、启停和运行时状态。Custom API 是例外：该账号仍拥有 Endpoint、协议和模型映射。无鉴权用户定义供应商只暴露一张单例账号，并拒绝第二张。

额度卡按目录能力而不是 Provider ID 决定行为。`usageAvailability=available` 时加载通用 Provider quota windows 并显示刷新动作；`manualUsageCalibration=true` 时额外加载本地校准对象供编辑，但卡片本身仍渲染 Provider windows。其余目录行不显示额度条；Zen Free 继续使用独立的出口冷却。已知 MiniMax/Kimi 窗口名保持友好显示，未知窗口名安全地人类化，不改存储 wire 值。Custom API 与用户定义 Provider 账号，若保存的 Endpoint 主机恰好是 `api.deepseek.com`、`api.moonshot.cn` 或 `api.moonshot.ai`，也可以点**刷新额度**读取官方当前余额。该快照只用于展示，不改变路由。其他 Custom 目的地在本产品中没有余额接口。

GOAT 卡片显示的是明确标注的本地估算：
OCG 内已定价请求日志按公开的 `$14 / $35 / $70` 三个窗口累计。Command Code 没有可机读的用量 API。其他客户端流量与未定价日志不会计入，
可通过手工校准修正显示基线。付费档 Ollama Cloud 卡片（Pro / Max / Team）把 OCG 内已定价请求日志投影到每月 `$60 / $300 / $1000` USD Credits 软额度。Ollama Cloud 在本产品中没有官方用量 API。实际已用可以超过软上限，进度条只把显示钳在 100%，满了也不会写冷却或改变路由。新建账号必须选择 Pro / Max / Team 并填写购买日期。既有无计费行的账号保持未配置且仍可路由，直到编辑档位。

## 在节点之间迁移配置

在账号页工具栏点击 **导出**，生成密码加密的 `.ocgbackup` 文件；再到目标节点点击
**导入**，先预览归并结果，再确认写入。迁移密码至少 12 个字符，
应与文件分开传递；Open Console Gateway 不会保存，也无法找回。迁移仍只允许从节点自己的回环面板执行；
转发的 scheme 请求头不会让远程面板获得迁移权限。

当前 V7 payload 会迁移目的地、凭据、可用普通账号及其稳定 ID、ready 账号 Key、Custom Endpoint/公开模型 → 上游 ID 映射与验证状态、
用户定义供应商（只有 `providerId`）、
主接入 Key 和所有有效子 Key、可迁移的路由/代理设置、Zen Free 启用状态与目录，Provider
目录、证据和协议覆盖，以及一份显式的身份 / 凭据 / 绑定 / 额度池快照。
共享身份、同一身份上的第二份凭据、绑定的模型限制与启用状态，以及额度池成员和已声明/未知证据都会按已存储内容恢复。同一稳定 ID 按迁移包内的可迁移字段原位归并；Plan 或名称相同但 ID 不同的
记录可以并存，独立的相同 URL 账号不会被合并。目标端已有账号保持当前顺序和位置，迁移包中新增的账号按包内顺序接在后面；目标端
独有接入 Key 和 Provider 范围也会保留。

浏览器 Profile/Cookie、第三方登录密码、邀请码、日志和用量历史不会迁移。V7 会携带来源端冷却截止时间，且不缩短目标端更晚的截止时间；V4/V5 的冷却行为只作用于本机。同 ID
账号在目标端已有的用量/冷却历史和浏览器数据继续保留，迁移包字段替换原凭据时会清除已经过时的
鉴权错误和最近错误。监听地址/端口、客户端根地址、开机启动和 Dock
图标等本机设置也保留目标端值。已完成托管账号会带上 Key，但浏览器登录不会迁移；未完成托管草稿
会直接跳过。导入接受 payload V4、V5、V6 与 V7。V4/V5 包会为每个账号重建一个身份、一份凭据、一条 All 范围绑定和该身份的额度池。导入 V1–V3 或 V8 及更新备份时会提示版本不受支持。若 V4/V5 文件已经带上 V6 身份字段，或 V6 文件已经带上 V7 目的地字段，导入会拒绝而不是静默丢弃。
外层加密 envelope 仍为 v1，与其中的 portable payload 版本相互独立。

所有持久化变更路径（数据库闸口，以及 dashboard / CLI 共用服务）都会在改动行、revision
或时间戳之前，拒绝为目录内真正 `routable=false` 的供应商设置 `enabled=true`。
GOAT 目录刷新更新模型目录；Key 鉴权从推理 401/403 观察。enabled、ready 且 Key 非空的账号可路由供应商矩阵中已启用的模型。新建且可路由的 Custom API 账号默认启用；编辑 Endpoint、能力、Key 或协议仍保持当前启用状态。禁用草稿仍可保存。为可刷新的内置供应商保存第一张就绪账号时，会自动做一次该供应商的 **刷新模型目录**；往已有连接再加 Key 不会重复刷新。账号创建成功后，目录刷新失败也不回滚。

OpenCode Go、Command Code GOAT、MiniMax Token Plan 与 Kimi Code 只接受各自官方 Provider API **Key**；浏览器 Cookie 与反向代理凭据不是账号
Key。GOAT 是独立的供应商映射，其 Key 只会发送到固定的 Command Code Provider
API，绝不发往 OpenCode。Custom API
是独立的受信管理员目的地，不能把 Key 发往 OpenCode endpoint。

MiniMax 与 Kimi 的 Key 同样绑定固定来源：MiniMax CN 使用
`https://api.minimaxi.com/v1`，Kimi Code CN 使用
`https://api.kimi.com/coding/v1`。模型和用量只在用户点击面板动作时访问；显示的用量不改变推理资格。第一次成功刷新用量前，账号卡仍显示一条中性的 **尚未刷新** 额度条；刷新成功后再由官方窗口替换。

Command Code 官方 `GET /models` 是公开的供应商级目录刷新。供应商矩阵是模型供应控制面：GOAT 预设默认开启，新发现模型默认关闭。

Custom API 是已上线的受信管理员目的地。**账号** 是唯一可编辑映射的页面：每行把公开模型名（客户端请求的名称）与精确上游模型 ID（OCG 实际发送的名称）配对。账号卡保存一个 API 地址、一个上游协议（Chat Completions、Responses 或 Messages）和至少一条映射。该协议对账号内全部映射统一生效，也是 effective preferred protocol：同协议客户端请求直接透传，其他受支持客户端格式统一转换到它。见[协议转换](protocol-conversion.zh-CN.md)。推荐填写不带 `/v1` 的来源根地址：OCG 会自动补上 `/v1` 与所选协议路径；已经以 `/v1` 结尾的基址不会重复添加。现有标准完整 Endpoint 继续原样使用。**获取模型** 会从根地址或版本基址得到 `/v1/models`，也可从标准完整 Endpoint 推导同级 `/models`；非标准完整路径仍原样用于推理，但不猜测目录地址，保留手动添加模型。发现结果只返回上游 ID；选择导入时公开名称与上游 ID 原样相同。获取不会保存、验证或启用账号。

受信管理员可配置公网、局域网或回环 HTTP / HTTPS 源。元数据、链路本地以及不透明 IPv4 把戏主机（例如
`169.254.169.254` 或 `metadata.google.internal`）会被拒绝。URL
内嵌凭据、query 与 fragment 会被拒绝。Gateway 拒绝重定向，也不会转发 dashboard 或客户端鉴权。
模型或 Endpoint 覆盖到另一 Origin 时，不会自动继承已保存的 Key。Chat Completions 与 Responses 使用 `Authorization: Bearer <key>`；Messages 使用 `x-api-key: <key>`。401 不会换用另一种鉴权头重试。根地址和 `/v1` 基址在模型发现、验证与正式推理中采用同一补全规则；历史完整 Endpoint 仍原样请求。Custom HTTP 使用同一套进程级 Direct / Manual / Auto 代理策略；连接与请求超时按配置的连接超时夹到
5–60 秒。

所有 ready 账号卡片使用同一个 **测试连接** 动作。弹窗提供可搜索的模型表格、单模型测试与顺序执行的 **测试全部**。每次测试只通过当前这一账号及其当前有效协议发送一次最小真实请求。测试留在该账号上：不切换其他账号，不走 Gateway fallback，不改变启停或冷却，也不写入 Provider 协议证据。结果只保留在当前弹窗；关闭后不再派发排队中的测试，已经发出的请求可按现有超时结束。测试可能消耗供应商额度。Provider 页的测试仍是独立的低频控制面，用于新增 Provider 模型时验证模型/协议能力，并可按其语义使用符合条件的账号回退。

合格账号（enabled + ready + 非空 Key）只会把可路由的**公开名称**暴露在带鉴权的 `GET /v1/models` 上。Custom 公开名称会解析到其配对的精确上游 ID，且不得抢占已发布的内置 Alias。raw 身份冲突会从发布列表中排除，并以 `ambiguous_model_id` 失败，绝不调用上游。未声明名称仍为未知（`400`）。更改 Endpoint、Key、映射或协议仍保持账号启用。Endpoint 与上游协议可在创建后编辑；配置与完整映射集通过一次 CAS 事务替换。禁用声明协议时，模型不可路由；不允许固定优先级回退或覆盖去启用未声明协议。Custom 流量仍为未定价：日志记录 `cost_state=unknown`，不扣额度，也没有 Custom 供应商用量刷新。`MODEL_PROTOCOLS` 只属于 Go；Custom 将客户端协议转换到账号唯一上游协议。

给现有供应商追加 Key 时，选择已有连接，不会再创建另一份供应商配置。新服务入口包含未使用的内置模板、Plan/API 预设、Custom API 与平台类型。搜索匹配厂商、变体、预设名称和端点主机；选中搜索结果后，清空搜索仍保留准确变体。Zen Free 是后端管理的单例，只在账号列表启停；OpenCode Go 在宿主支持时提供可选的托管注册入口。

- **Key 账号** 直接保存一份官方分发的 OpenCode Go API Key。
- **托管账号** 先创建一条禁用的可恢复草稿，再按向导完成登录身份（可选）、邀请注册、支付、Key
  验证。草稿与当前步骤会立即写入 SQLite；关闭页面或重启服务后可继续。注册中账号不会参与
  Gateway 路由，也不会显示用量、验证或启用控件。

托管注册与独立浏览器 Profile 是 **Beta** 功能，尚未经过充分测试；生产环境仍不建议依赖。

创建托管草稿时会直接展示 **邀请链接**（预填 OpenCode Go 供应商中的当前值；新安装默认带演示链接）。可当场编辑：须为无用户名/密码、最长
2048 字符的 HTTPS URL，主机只能是 `opencode.ai` 或 `console.opencode.ai`。与已保存值不同时会写回
**供应商 → OpenCode Go → 设置**；修改只影响以后打开邀请页，不会改写已完成账号。默认演示链接仅供试用，正式注册前请换成你自己的邀请链接，否则邀请收益归链接所有者。

托管向导是纯人工流程（不代填密码、不代点支付、不自动提取 Key）：

1. **登录身份（可选）**：需要新账号时再注册 Google 或 GitHub；已有任一账号可 **跳过此步**。OpenCode
   登录也可在下一步完成。
2. **邀请注册**：在同一独立 Profile 中打开邀请链接，用 Google 或 GitHub 完成 OpenCode 登录/注册。
3. **完成支付**：在控制台确认套餐与金额；支付仅由你在页面上完成。
4. **验证 Key**：从控制台复制 Key，粘贴后由 Open Console Gateway 真实请求上游验证。

点击步骤条可 **回退到已完成的更早步骤**；前进仍靠各步主按钮。验证返回 `2xx`
时账号完成并启用；`429` 也表示 Key 有效，账号会完成并记录现有冷却；`401`/`403`、网络错误或
`5xx` 会停留在 Key 验证步骤，允许修正后重试。

每个账号都有长期独立的浏览器 Profile。桌面端会启动外部 Chromium 系浏览器：Windows 优先
Edge、其次 Chrome；macOS 查找 Chrome、Edge、Chromium；Linux 桌面从 `PATH` 查找 Chrome、Chromium
或 Edge。浏览器仅使用独立 `browser-profiles/<account_id>`、跳过首次运行提示并打开新窗口，不启用
CDP、自动化或降低安全性的参数。

所有 ready 的 OpenCode Go 账号都提供 **打开 OpenCode 控制台**（`https://opencode.ai/auth`）。第一次打开时是空白的独立
Profile，登录一次后 Cookie 会长期保留。Google / GitHub 与 OpenCode 的 Cookie
分属不同域，但都保存在该账号的同一个 Profile 中。

重置浏览器身份会先关闭该账号的浏览器并删除新旧 Profile：完成注册的账号保留 Key，只退出控制台登录；注册中的托管账号还会回到登录身份步骤。删除账号也会删除浏览器
Cookie/Profile，确认框会明确提示这一点。之后这些登录状态无法从 Open Console Gateway
恢复，只能从备份恢复或重新登录。

每张 ready 的 OpenCode Go 或 GOAT 账号卡都显示账号名、冷却状态，以及 5 小时、本周、本月用量条。
OpenCode Go 会通过官方端点定期校准本地核算；GOAT 用量条是 OCG 内已定价日志的本地投影。
Zen Free 使用独立的匿名、按出口 IP 共享的 free 冷却，不使用某个 Key 的额度。

- **用量校准**：每个窗口都可以输入百分比或拖动进度条，将其保存为当前实际用量基线；保存后，OCG
  Manager 记录的成功请求成本会继续累加到该基线上。达到 100% 仍只是提示，不会阻止 Gateway
  选择这个账号。只有 Plan 明确声明该能力时才显示手工校准；GOAT 用它修正 OCG 无法观察到的其他流量。
- **刷新额度（已完成的 Key / 托管账号）**：官方用量（`/zen/go/v1/usage`）只是周期性校准基线；本节点转发日志成本仍是实时估算。活跃的
  ready 账号约每小时自动对账，不活跃的约每天一次；禁用、未完成或空 Key
  账号不会自动刷新，打开账号页不会触发请求。Gateway 启动时不会立即请求；尚无已保存调度的合格账号会分散到最初
  0–15 分钟内，再按正常节奏对账。点击 **刷新额度** 仍走同一条安全路径，服务端每账号 15
  秒节流（返回 Retry-After / next-allowed）。卡片会显示上次成功官方同步时间，而不仅依赖按钮
  loading。本地估算达到 ≥80% 时最多每 15 分钟加速对账一次。真实推理 `429`
  仍写入现有冷却/选择器状态，并额外在约 1–2 分钟后调度一次官方对账；官方失败或
  `status=rate-limited` 不会写推理冷却。失败保留上次基线与 last-success。请求走与其他面板出站相同的全局代理。
- **标识与凭据**：名称是必填的主要展示标识。登录账号可选；新增 Key
  账号时如果先填写账号，它会自动同步为名称，手动修改名称后不再跟随。可选备注写在 **编辑账号**
  里，可留空，不参与路由、不计入额度。面板保存账号 Key，但不收集或维护第三方登录密码。
- **购买日期**：具有购买周期的新账号默认使用浏览器当天。点击账号卡上的到期标签，可以快速选择其他购买日期或直接更新到今天；完整编辑表单仍可使用。托管向导在确认支付进入
  Key 验证时也会写入购买日期。到期日取下一个自然月同日；目标月份没有该日时取月末，例如
  `2026-01-31` 的到期日是 `2026-02-28`。账号页与仪表盘显示剩余天数、今天到期或已到期天数。该信息只作提醒，不会自动禁用账号或阻止
  Gateway 选择。Zen Free 与 Custom API 没有购买周期到期语义，因此不显示到期标签或提醒。
- **优先级顺序**：账号列表按目的地（供应商、Custom API 地址或平台站点）分组显示 Key，所有组共用一个全局路由顺序。只有一把 Key 的目的地显示为一张卡；有多把 Key 的目的地显示目的地头部和每把 Key 一行。卡片左侧的拖动手柄移动整个组，鼠标、触屏和触控笔都可以使用；聚焦手柄后也可以按上、下方向键移动。组内的 Key 用行菜单里的 **上移** / **下移** 调整顺序，不会离开所在组。排序保存在当前节点的
  SQLite 中，仪表盘、日志账号筛选、CLI 列表和 Gateway 选择器都使用同一顺序。
- **解除冷却**：冷却也可以在这个视图手动解除。解除后，进度条会立刻回到本地估算值。
