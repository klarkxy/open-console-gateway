# 账号

Custom API 的地址、协议和模型映射在账号中编辑，即使它拥有多把 Key。用户定义的 HTTP 供应商则在 **供应商** 页面编辑这些配置，即使它只有一把 Key。只有已建模订阅周期的 Plan 展示到期信息；CPA 和用户定义的 API／Plan 预设不展示推断的订阅周期。

在账号列表上方的 **账号路由** 下拉菜单选择方案，旁边的 **对话粘性** 开关可独立启停。修改后立即保存，成功后重置运行时路由状态。悬停或用键盘聚焦问号按钮可查看说明。

- **路由方案**：严格优先级、全局粘性或轮询。三种方案都会先过滤不兼容、禁用、冷却或本请求已失败的卡片，再使用同一份全局卡片顺序。同一时刻只能启用一种基础方案。
- **对话粘性**：叠加开关，不是第四种路由方案。开启后优先使用请求头 `X-OCG-Conversation-Id`；未提供时用 Prompt 指纹（system / tools / 首条 user）。无法生成会话 key 时回退基础路由。相似提示词可能绑到同一账号。

**新增账号** 先区分已有连接与新服务。已有连接与 **供应商** 页使用同一套连接投影：只有至少还有一张账号的内置供应商，以及已保存的用户定义供应商（有无 Key 都列出）。删掉某个内置供应商的最后一张账号后，它会离开已有连接，回到新服务里的内置模板。选择已有连接会沿用其已保存的地址、协议和模型，只添加另一把 Key。选择新服务，再浏览未使用的内置模板、Plan/API 预设、Custom API 或平台站点。保存预设会同时创建供应商和首个账号。**供应商 → 添加供应商** 打开同一套选择器。从 **新增账号** 保存预设时，使用与 **供应商** 页相同的 onboarding commit。填写 Key 前始终可查看连接摘要，地区和套餐变体使用紧凑选择器。Key 由账号服务保存；你可以在本页添加，也可以在供应商详情里用 **添加 Key**。

供应商选项来自 V4 目的地与目录投影，在选择器中按名称排列；添加新服务时 Custom API 固定首位。选择器、筛选、弹窗与缓存都使用 `provider_id`。成功返回空目录就保持为空；目录加载失败时只保留 OpenCode Go 创建表单，既有 Zen Free 单例仍可展示，其余内置、Custom 与用户定义入口全部失败关闭。名称、服务类型、创建状态与表单字段都来自目录行，选择器不再按 Plan/API 分组。密封供应商的第一张就绪账号保存后，面板先读取该供应商现有 Contract 的目录刷新能力，再决定是否刷新；追加第二把 Key 不重复刷新。能力查询或刷新失败不会回滚已经保存的账号，可到 **供应商 → 刷新模型目录** 重试。

**已启用** 表示这个账号可以进入路由。新建就绪 Key 账号（含 Custom API 与用户定义供应商）默认启用。测试连接不会改变开关。已经开启或关闭的账号保持原状态。测试结果保留在测试弹窗中。用户定义供应商没有建模订阅周期，包括从 Plan 预设创建的供应商：其账号不显示推算的购买日期、到期倒计时或到期提醒。既有存储中的购买日期锚点保留兼容，但不作为已经确认的计费事实展示。

账号使用与创建时相同的表单编辑。就绪且可路由的卡片只显示已启用、已禁用、冷却、额度耗尽或不可用。动态、Custom 和 CPA 账号不显示推断的订阅周期，即使兼容数据中存有购买日期。

有效 `429` 会临时冷却收到它的 Key；已确认的额度耗尽也会使该 Key 变暗，**已启用**开关保持原状。关掉某个 Key 的开关会立刻置灰那一行。只有卡内每一个 Key 都置灰（禁用、无效、冷却、额度耗尽或其它不可路由）时，整张卡片才置灰。空卡显示无 Key。每张展示卡片只看自己的行。

就绪的 Key 行可从溢出菜单 **轮换 Key**、**添加 Key** 和 **编辑绑定**。轮换只替换本机此后请求使用的 Key（凭据 id 不变，版本号递增），是本地替换：不会撤销供应商侧的原凭据，仍由你自行管理。轮换或替换 Key 会清除绑定旧 Key 版本的本机状态。**添加 Key** 只有在服务端允许该连接创建凭据且接受提交的材料类型时才会创建另一把推理 Key；拒绝时返回共用原因。额度默认独立；只有你明确选择与同一身份下某把已有推理 Key 共享时才会共享，不会因为使用同一连接或身份而自动共享。保存后，卡片按已存储的额度池显示实际共享关系（能确定时会写出共享的那把 Key）。第三把 Key 若有自己的池或没有池，仍是独立额度。包括迁移后 Custom API 记录在内的可配置 HTTP 连接都支持多把 Key。Zen Free、CPA、无鉴权和观察者凭据仍是单例或由外部管理，不提供添加 Key。CPA 订阅池卡片还会显示 OCG 托管运行时是运行中、已停止、未安装，还是处于安装/启动过程；外部连接的 CPA 只标为外部连接，不会把 OCG 并未拥有的进程报成运行或停止。运行中或外部连接的池保持正常可用卡片；托管进程已停止、未安装或失败时卡片置灰，不拨动已启用开关。若创建没有得到确定结果，表单会锁定已提交的内容和操作：用相同内容重试，或取消；不要改内容后再提交（可能产生重复 Key）。

编辑绑定可改该凭据绑定的启用状态、模型范围（全部模型，或仅你列出的准确名称），以及——仅在你改动时——目标同意：允许此 Key 发往哪些已配置端点（协议和 URL）。当前 endpoint 只从这条精确凭据已保存的 grants 解析，同级 Key 不会借出 Origin。供应商地址日后更改时，仍显示已保存的 Origin，该端点保持未勾选，除非你明确允许新目标。只改范围或启用时不会改目标。两个目标列表都清空即撤销。没有 URL 的官方锁定端点保持官方目标，不会编造 Origin 字符串。绑定禁用显示在该卡片上，不会拨动账号启用开关。Zen Free、CPA、无鉴权和观察者凭据不提供轮换或绑定。一个身份可以持有多把 Key；每个账号行只用 `legacy` 账号 id 与自己匹配的那份凭据。

账号按供应商卡片管理，每张卡可包含多个账号 / Key，同一供应商可有多张卡。卡片共用供应商的地址、协议和模型配置；移动账号保留其凭据、授权、用量、额度池、冷却和本机状态。Provider 与 Plan 仍是同一个产品身份（只有 `provider_id`）。OpenCode Go 按账号 / Key 统计额度，Zen Free 按出口 IP 共享额度与冷却，Custom API 不做供应商额度核算。页面按卡片、再按卡内账号展开后的顺序就是路由优先级；严格优先级、全局粘性和轮询复用这份顺序。不存在按模型划分的额度池。普通冷却可通过**已声明额度池**扇出；`429` 冷却只留在收到它的 Key。

**账号** 负责身份、账号 **Key**、验证、启用状态、卡片顺序、托管注册，以及可用的账号用量
/ 冷却 / 额度恢复状态。本地目录、协议探测、按模型协议覆盖、用户定义供应商的 Endpoint/协议/映射，以及范围内价格都在
**供应商** 页。账号只保存 Key（鉴权需要时）、备注、启停、模型范围、发送授权、额度关系和运行时状态；Endpoint、鉴权、协议和模型映射归连接所有。无鉴权连接只暴露一份单例凭据，并拒绝第二份。

额度卡按目录能力而不是 Provider ID 决定行为。`usageAvailability=available` 时加载通用 Provider quota windows 并显示刷新动作；`manualUsageCalibration=true` 时额外加载本地校准对象供编辑，但卡片本身仍渲染 Provider windows。其余目录行不显示额度条；Zen Free 继续使用独立的出口冷却。已知 MiniMax/Kimi 窗口名保持友好显示，未知窗口名安全地人类化，不改存储 wire 值。Custom API 与用户定义 Provider 账号，若保存的 Endpoint 主机恰好是 `api.deepseek.com`、`api.moonshot.cn` 或 `api.moonshot.ai`，也可以点**刷新额度**读取官方当前余额。按量 API 卡（DeepSeek / 智谱预设和 New API / Sub2API 站点）用 **余额**、**本月**、**历史** 三个数字展示，不用额度条。已知主机的官方余额仍只显示剩余。**刷新额度**会同时刷新该目的地的模型列表（内置 Plan 走官方目录刷新；Custom / 已知主机余额卡和平台 Key 走 `/v1/models` 发现），不必只为刷新目录再打开**供应商**页。内置目录行遵循各供应商的默认启用规则；GOAT 首次快照只开启套餐包含的模型。用量快照只用于展示：进度条到 100%、未知或失败都不会把 Key 标为耗尽，也不改变路由。其他 Custom 目的地在本产品中没有余额接口。

GOAT 卡片可通过 **刷新额度** 从 Command Code 第一方账号用量读取 `$14 / $35 / $70` 三个窗口。该端点由官方 CLI 使用，但未列入公开 Provider API 文档。两次快照之间继续本地累计 OCG 内已定价请求日志。官方快照就是基线，卡片不再提供手工校准。月窗口重置时间仍由已配置的购买日期推导，不是上游返回的月重置时间。付费档 Ollama Cloud 卡片（Pro / Max / Team）把 OCG 内已定价请求日志投影到每月 `$60 / $300 / $1000` USD Credits 软额度。Ollama Cloud 在本产品中没有官方用量 API。实际已用可以超过软上限，进度条只把显示钳在 100%，满了也不会写冷却或改变路由。新建账号必须选择 Pro / Max / Team 并填写购买日期。既有无计费行的账号保持未配置且仍可路由，直到编辑档位。

## 个人积分估算

Custom API 与已保存的可配置 HTTP 账号可以记录个人积分余额。在 **添加 Key** 或该 Key 的 **编辑** 表单中初始化：Step Plan 提供档位、当前剩余和重置日期；其他 HTTP 账号可以选择 **本地积分估算**，按精确上游模型 ID 填写费率。卡片展示已保存的余额，后续修正使用 Key 操作区的 **校准用量**。月度发放和有到期时间的加油包仍分别记录。同一供应商下的每把 Key 独立估算。New API / Sub2API 站点 Key 和内置 Plan 保留原有计费视图，暂不提供个人积分编辑器。

修改 Key 会保留已有积分账本。如果 Key 已保存但额度初始化失败，在原表单中重试即可继续初始化，不会重复创建 Key；也可以关闭表单，之后从该 Key 的 **编辑** 入口补齐。

请求完成时按本次尝试开始时的价格扣减积分。缺少用量或价格时保留未知，不记为零。校准需要等在途请求完成；修改价格不会重置当前余额。估算余额为零也不会停用路由。Step Plan 使用本地估算和手工校准，不读取私有控制台用量接口。

V11 备份携带积分设置与剩余额度。合并导入保留目标已有账本，在途请求作为估算不确定性导出。详见[升级与备份](upgrade-backup.zh-CN.md)。

## 在节点之间迁移配置

同 ID 的供应商与模型按来源备份恢复启用状态、已启用协议和首选协议；目标独有模型保留。上游映射或地址覆盖冲突时整笔拒绝。无鉴权 HTTP 连接也可导出和恢复。

在账号页工具栏点击 **导出**，生成密码加密的 `.ocgbackup` 文件；再到目标节点点击
**导入**，先预览归并结果，再确认写入。迁移密码至少 12 个字符，
应与文件分开传递；Open Console Gateway 不会保存，也无法找回。迁移仍只允许从节点自己的回环面板执行；
转发的 scheme 请求头不会让远程面板获得迁移权限。

当前 V11 payload 以目的地与凭据为权威（ready Key、平台与 CPA observer 管理凭据，以及 identity / grant / cooldown extras 只存在加密信封内），
并迁移写在这些实体上的 Custom Endpoint/公开模型 → 上游 ID 映射与验证状态、作为目的地 extras 的用户定义供应商、
主接入 Key 和所有有效子 Key、可迁移的路由/代理设置、Zen Free 启用状态与目录，Provider
目录、证据、协议覆盖和显式 HTTP 协议路由，以及额度池成员关系。
共享身份、同一身份上的第二份凭据、绑定的模型限制与启用状态，以及额度池成员和已声明/未知证据都会按已存储内容恢复。V7 Custom 目的地会规范化为连接所有、多 Key 的结构，同时保持稳定 ID 与仅公开名称解析。同一稳定 ID 按迁移包内的可迁移字段原位归并；Plan 或名称相同但 ID 不同的
记录可以并存，独立的相同 URL 账号不会被合并。目标端已有账号保持当前顺序和位置，迁移包中新增的账号按包内顺序接在后面；目标端
独有接入 Key 和 Provider 范围也会保留。合并导入时，若包中没有 CPA observer key，会保留目标已有 management key。

浏览器 Profile/Cookie、第三方登录密码、邀请码、日志和用量历史不会迁移。本机额度恢复状态不导出。导入若未替换目标 Key，则保留该本机恢复；替换 Key 会清除。V9 会携带来源端冷却截止时间，且不缩短目标端更晚的截止时间；V4/V5 的冷却行为只作用于本机。同 ID
账号在目标端已有的用量/冷却历史和浏览器数据继续保留，迁移包字段替换原凭据时会清除已经过时的
鉴权错误和最近错误。监听地址/端口、客户端根地址、开机启动和 Dock
图标等本机设置也保留目标端值。已完成托管账号会带上 Key，但浏览器登录不会迁移；未完成托管草稿
会直接跳过。导入接受 payload V4、V5、V6、V7、V8、V9、V10 与 V11。没有协议路由的 V4–V10 包仍兼容；早于 V11 但携带非空显式路由的包会被拒绝，避免丢失这些路由。V4/V5 包会为每个账号重建一个身份、一份凭据、一条 All 范围绑定和该身份的额度池。导入 V1–V3 或 V12 及更新备份时会提示版本不受支持。若旧版本文件已经带上新版本的身份、目的地或卡片字段，导入会拒绝而不是静默丢弃。
外层加密 envelope 仍为 v1，与其中的 portable payload 版本相互独立。

所有持久化变更路径（数据库闸口，以及 dashboard / CLI 共用服务）都会在改动行、revision
或时间戳之前，拒绝为目录内真正 `routable=false` 的供应商设置 `enabled=true`。
GOAT 目录刷新更新模型目录；Key 鉴权从推理 401/403 观察。enabled、ready 且 Key 非空的账号可路由供应商矩阵中已启用的模型。新建且可路由的 Custom API 账号默认启用；编辑 Endpoint、能力、Key 或协议仍保持当前启用状态。禁用草稿仍可保存。为可刷新的内置供应商保存第一张就绪账号时，会自动做一次该供应商的 **刷新模型目录**；往已有连接再加 Key 不会重复刷新。账号创建成功后，目录刷新失败也不回滚。

OpenCode Go、Command Code GOAT、MiniMax Token Plan 与 Kimi Code 只接受各自官方 Provider API **Key**；浏览器 Cookie 与反向代理凭据不是账号
Key。GOAT 是独立的供应商映射，其 Key 只会发送到固定的 Command Code 推理和账号用量端点，
绝不发往 OpenCode；公开目录刷新仍不带 Key。Custom API
是独立的受信管理员目的地，不能把 Key 发往 OpenCode endpoint。

MiniMax 与 Kimi 的 Key 同样绑定固定来源：密封 MiniMax CN 的推理与目录路由使用
`https://api.minimax.cn/v1` 及文档化的 `/anthropic` 路由；旧用量端点保持不变。Kimi Code CN 使用
`https://api.kimi.com/coding/v1`。模型和用量只在用户点击面板动作时访问；显示的用量不改变推理资格。第一次成功刷新用量前，账号卡仍显示一条中性的 **尚未刷新** 额度条；刷新成功后再由官方窗口替换。

Command Code 官方 `GET /models` 是公开的供应商级目录刷新。账号卡点 **刷新额度** 时也会跑这次目录刷新。供应商矩阵仍是模型供应控制面：首次快照只默认开启 GOAT 套餐模型，其他模型先保持关闭；以后刷新中新出现且有文档化端点的模型默认开启。保存的开关状态会保留，没有协议证据的模型等待官方资料。

Custom API 是已上线的受信管理员目的地。**供应商** 编辑映射：每行把公开模型名（客户端请求的名称）与精确上游模型 ID（OCG 实际发送的名称）配对。一条连接使用遗留路由，或保存一到三条显式 Chat Completions、Responses、Messages 路由；每条路由都有自己的端点和鉴权。映射继承所属协议的路由，除非它保存一条单独的上游覆盖。**账号** 只编辑挂在该连接上的 Key 和绑定。已有完整 Endpoint 继续原样使用。**获取模型** 使用保存的目录路由；非标准路由仍原样用于推理，不猜测目录地址，保留手动添加模型。发现结果只返回上游 ID；选择导入时公开名称与上游 ID 原样相同。获取不会保存、验证、启用或授权 Key。

受信管理员可配置公网、局域网或回环 HTTP / HTTPS 源。元数据、链路本地以及不透明 IPv4 把戏主机（例如
`169.254.169.254` 或 `metadata.google.internal`）会被拒绝。URL
内嵌凭据、query 与 fragment 会被拒绝。Gateway 拒绝重定向，也不会转发 dashboard 或客户端鉴权。
模型或 Endpoint 覆盖到另一 Origin 时，不会自动继承已保存的 Key。可配置 HTTP 路由按已保存的鉴权方式发送 `Authorization: Bearer <key>`、`x-api-key: <key>` 或 `api-key: <key>`。401 不会换用另一种鉴权头重试。根地址和 `/v1` 基址在模型发现、验证与正式推理中采用同一补全规则；历史完整 Endpoint 仍原样请求。Custom HTTP 使用同一套进程级 Direct / Manual / Auto 代理策略；连接与请求超时按配置的连接超时夹到
5–60 秒。

所有 ready 账号卡片使用同一个 **测试连接** 动作。弹窗提供可搜索的模型表格、单模型测试与顺序执行的 **测试全部**。每次测试只通过当前这一账号及其当前有效协议发送一次最小真实请求。测试留在该账号上：不切换其他账号，不走 Gateway fallback，不改变启停、冷却或额度恢复，也不写入 Provider 协议证据。测试不是额度恢复试探。结果只保留在当前弹窗；关闭后不再派发排队中的测试，已经发出的请求可按现有超时结束。测试可能消耗供应商额度。Provider 页的测试仍是独立的低频控制面，用于新增 Provider 模型时验证模型/协议能力，并可按其语义使用符合条件的账号回退。

合格账号（enabled + ready + 非空 Key）只会把可路由的**公开名称**暴露在带鉴权的 `GET /v1/models` 上。迁移而来的 Custom 连接继续只接受原有公开名称；新建普通自定义 HTTP 连接还可用唯一的精确上游 ID。raw 身份冲突会从发布列表中排除，并以 `ambiguous_model_id` 失败，绝不调用上游。未声明名称仍为未知（`400`）。更改 Endpoint、映射或协议仍保持各账号启用，也不会自动把 Key 授权给新目标；保存时只为明确选择的 Key 增加授权。配置与完整映射集通过一次 CAS 事务替换。禁用声明协议时，模型不可路由；不允许固定优先级回退或覆盖去启用未声明协议。Custom 流量在未为精确上游模型设置个人积分费率时费用未知。个人估算不扣服务商额度，也没有 Custom 供应商用量刷新。`MODEL_PROTOCOLS` 只属于 Go；Custom 将客户端协议转换到连接的上游协议。

给现有供应商追加 Key 时，选择已有连接，不会再创建另一份供应商配置。新服务入口包含未使用的内置模板、Plan/API 预设、Custom API 与平台类型。搜索匹配厂商、变体、预设名称和端点主机；选中搜索结果后，清空搜索仍保留准确变体。Zen Free 是后端管理的单例，只在账号列表启停；OpenCode Go 在宿主支持时提供可选的托管注册入口。

- **Key 账号** 直接保存一份官方分发的 OpenCode Go API Key。
- **托管账号** 先创建一条禁用的可恢复草稿，再按向导完成登录身份（可选）、邀请注册、支付、Key
  验证。草稿与当前步骤会立即写入 SQLite；关闭页面或重启服务后可继续。注册中账号不会参与
  Gateway 路由，也不会显示用量、验证或启用控件。

托管注册与独立浏览器 Profile 是 **Beta** 功能，尚未经过充分测试；生产环境仍不建议依赖。

创建托管草稿时会直接展示 **邀请链接**（预填 OpenCode Go 供应商中的当前值；新安装默认带演示链接）。可当场编辑：须为无用户名/密码、最长
2048 字符的 HTTPS URL，主机只能是 `opencode.ai` 或 `console.opencode.ai`。与已保存值不同时会写回
**供应商 → OpenCode Go → 设置**；修改只影响以后打开邀请页，不会改写已完成账号。默认演示链接仅供试用，正式注册前请换成你自己的邀请链接，否则邀请收益归链接所有者。

托管向导是纯人工流程（不代填密码、不代点支付、不自动提取 Key）：

1. **登录身份（可选）**：需要新账号时再注册 Google 或 GitHub；已有任一账号可 **跳过此步**。OpenCode
   登录也可在下一步完成。
2. **邀请注册**：在同一独立 Profile 中打开邀请链接，用 Google 或 GitHub 完成 OpenCode 登录/注册。
3. **完成支付**：在控制台确认套餐与金额；支付仅由你在页面上完成。
4. **验证 Key**：从控制台复制 Key，粘贴后由 Open Console Gateway 真实请求上游验证。

点击步骤条可 **回退到已完成的更早步骤**；前进仍靠各步主按钮。验证返回 `2xx`
时账号完成并启用；`429` 也表示 Key 有效，账号会完成并记录现有冷却；`401`/`403`、网络错误或
`5xx` 会停留在 Key 验证步骤，允许修正后重试。

每个账号都有长期独立的浏览器 Profile。桌面端会启动外部 Chromium 系浏览器：Windows 优先
Edge、其次 Chrome；macOS 查找 Chrome、Edge、Chromium；Linux 桌面从 `PATH` 查找 Chrome、Chromium
或 Edge。浏览器仅使用独立 `browser-profiles/<account_id>`、跳过首次运行提示并打开新窗口，不启用
CDP、自动化或降低安全性的参数。

所有 ready 的 OpenCode Go 账号都提供 **打开 OpenCode 控制台**（`https://opencode.ai/auth`）。第一次打开时是空白的独立
Profile，登录一次后 Cookie 会长期保留。Google / GitHub 与 OpenCode 的 Cookie
分属不同域，但都保存在该账号的同一个 Profile 中。

重置浏览器身份会先关闭该账号的浏览器并删除新旧 Profile：完成注册的账号保留 Key，只退出控制台登录；注册中的托管账号还会回到登录身份步骤。删除账号也会删除浏览器
Cookie/Profile，确认框会明确提示这一点。之后这些登录状态无法从 Open Console Gateway
恢复，只能从备份恢复或重新登录。

每张 ready 的 OpenCode Go 或 GOAT 账号卡都显示账号名、冷却状态，以及 5 小时、本周、本月用量条。
OpenCode Go 会通过官方端点定期校准本地核算；GOAT 只在点击 **刷新额度** 时校准，随后在官方基线上继续累计 OCG 内已定价日志。
Zen Free 使用独立的匿名、按出口 IP 共享的 free 冷却，不使用某个 Key 的额度。

- **用量校准**：每个窗口都可以输入百分比或拖动进度条，将其保存为当前实际用量基线；保存后，OCG
  Manager 记录的成功请求成本会继续累加到该基线上。达到 100% 仍只是提示，不会阻止 Gateway
  选择这个账号。只有 Plan 明确声明该能力时才显示手工校准；Ollama Cloud 没有官方用量 API，因此仍用它。
- **刷新额度（已完成的 Key / 托管账号）**：既有 OpenCode Go 调度器继续按既定节奏从 `/zen/go/v1/usage` 校准本地估算；不新增全局轮询循环。点击 **刷新额度** 走同一条节流并发合并的路径。真实 `429` 会立即启动临时 Key 冷却，并可排入同一条异步刷新而不让客户端请求等待。获取到的 Go 用量可以建立或清除 Go 额度状态。失败、限流或不支持的刷新保留原有观测或未知，绝不写推理冷却或 `auth_error`。请求走与其他面板出站相同的全局代理。
- **刷新 GOAT 额度**：GOAT 卡片只在用户显式点击后，使用该账号 Key 请求固定第一方端点
  `https://api.commandcode.ai/alpha/billing/credits`。OCG 会校验 GOAT 的 5 小时、周、月上限，再原子替换三个基线。
  此路径同样有每账号 15 秒节流并使用全局代理，但没有自动调度；结果不会写推理冷却或改变路由。不再提供单独的手工校准。
- **GOAT 推理限制**：每个 `429` 都启动同一套 30 秒临时 Key 冷却；有效 `Retry-After` 可以延长但绝不缩短它。GOAT 的错误文本、上限和展示用量都不能建立或清除持久化额度状态。见[路由](routing.zh-CN.md)。
- **标识与凭据**：名称是必填的主要展示标识。登录账号可选；新增 Key
  账号时如果先填写账号，它会自动同步为名称，手动修改名称后不再跟随。可选备注写在 **编辑账号**
  里，可留空，不参与路由、不计入额度。面板保存账号 Key，但不收集或维护第三方登录密码。
- **购买日期**：具有购买周期的新账号默认使用浏览器当天。点击账号卡上的到期标签，可以快速选择其他购买日期或直接更新到今天；完整编辑表单仍可使用。托管向导在确认支付进入
  Key 验证时也会写入购买日期。到期日取下一个自然月同日；目标月份没有该日时取月末，例如
  `2026-01-31` 的到期日是 `2026-02-28`。账号页与仪表盘显示剩余天数、今天到期或已到期天数。该信息只作提醒，不会自动禁用账号或阻止
  Gateway 选择。Zen Free 与 Custom API 没有购买周期到期语义，因此不显示到期标签或提醒。
- **优先级顺序**：直接调整卡片和卡内账号的排列，无需切换排序视图。卡片整体移动，卡内账号也可单独排序或移到同一供应商的另一张卡片。需要 `A1 → B1 → A2` 时，为 A 新建另一张卡并移入 A2。拖动与键盘操作保存同一份顺序；筛选状态下不能排序，避免改变隐藏账号的位置。空卡和相邻同供应商卡都会保留。
- **卡片折叠与排序模式**：卡片标题栏的折叠箭头可以把卡片收成一行摘要（Key 总数与启用数）；折叠只是本地视图状态，会在当前浏览器中保留，刷新页面后仍然生效。卡片的 ⋯ 菜单也提供 **上移**、**下移**、**移到顶部**、**移到底部**，与拖拽走同一份整体布局写入。工具栏的 **调整顺序** 按钮切换到紧凑排序模式：筛选被绕过并置灰，所有卡片与 Key 都以单行显示、可直接拖拽，点 **完成** 退出并恢复之前的筛选与折叠状态。
- **解除冷却**：普通冷却也可以在这个视图手动解除。解除后，进度条会立刻回到本地估算值。
- **429 冷却**：`429` 会冷却收到它的精确 Key 30 秒，除非有效 `Retry-After` 给出更晚截止时间。它不扩散到额度池同级 Key，到期后不会发送后台探测。保留的历史额度状态不会被批量清除；获取到的权威 Go 用量才会对 Go 状态进行对账。
