# 路由、费用与故障转移

请求从已保存的目的地模型目录解析模型身份，再按全局顺序选择凭据。供应商、凭据、模型的启用状态，协议选择、模型范围和显式 Endpoint 授权共同约束发送。配置异常会明确失败，不回退到重建的旧账号逻辑。每个请求固定模型映射和传输配置，每次发送重新检查当前授权、Key 版本、冷却和保留的权威 Go 额度状态；配置变化使旧候选失效，不会悄悄重定向。

**账号** 页从上到下的卡片顺序，再加上每张卡片内的 Key 顺序，就是保存的路由优先级。拖动卡片可整体移动其中的 Key，也可在卡内排序，或把 Key 移到同一供应商的另一张卡片。需要 `A1 → B1 → A2` 时，为 A 再建一张卡片即可，两张 A 卡共用已保存的供应商配置；相邻卡片也不会自动合并。严格优先级、轮询和粘性继续使用原有策略。

### OpenCode Go 新发现的模型

在供应商页刷新模型目录后，已知受支持上游协议的新模型会自动开启；没有协议证据的模型会保持不可用，直到获得相应证据。已保存到 Go 目录的模型按有效模型合约处理，即使代码中没有静态别名或协议条目，诊断计划也不会仅因为它是新模型而拒绝请求。明确关闭或删除的模型不会因此重新启用，推理时也不会试探协议。本地目录与协议测试不代表真实账号已获得模型权限。

### 429 冷却与官方观测

每个上游 `429` 都为收到它的精确 Key 启动临时冷却：没有可用约束时为 30 秒。有效的 `Retry-After` 延迟或 HTTP 日期可以延长等待，绝不缩短已有的更晚截止时间。该冷却不会显示为额度重置时间，也不通过已声明额度池扩散。Zen Free 保留独立的匿名出口 IP 恢复规则，不绑定到某把 Key。

Gateway 绝不从 HTTP 状态、错误正文或正文文本推断持久化额度或余额耗尽。`403` 只在本次请求内处理，不会持久化 `auth_error`。MiniMax 仍校验结构化错误信封，包括 HTTP 200 返回的错误信封，但其代码和消息不会创建持久化额度或余额状态。

出现 `429` 后，Gateway 可为支持它的 adapter 排入异步、合并且节流的官网用量刷新；客户端请求不会等待该工作。获取到的权威 OpenCode Go 用量可以建立或清除 Go 额度状态。除非 adapter 明确声明不同权威，GOAT 与 CN 用量快照只用于展示。刷新失败或不支持时保留上次观测，或保持未知。既有持久化额度回合不会被批量清除；新的错误响应不会创建它们。

## 账号选择与切换

在**别名**页展开模型即可读取只读路由解释：解析后的映射、合格连接与 Key、上游协议、全局顺序、结构化排除原因，以及基础策略当前预计首选。预览不会发送上游请求、解密 Key、写冷却、额度状态或日志，也不会推进粘性或轮询状态。它不模拟对话绑定、本次重试排除、快照后的状态变化或上游结果，因此解释的是观察时的基础策略，不是送达保证。

账号按 **列表顺序** 尝试，你可以在账号页拖动排序并持久保存。选择器会跳过以下对象：

- 已禁用账号；
- 处于冷却中的账号；
- 有效临时 `429` 等待的 Key，以及额度恢复截止时间尚未到期的 Key；
- 已经在本次请求里失败过的账号（例如拿到 `429`）；
- 已保存供应商合约对该解析模型没有 effective 启用上游协议的账号；
- 推理绑定已停用、或绑定 `modelScope` 不包含当前请求的公开/路由模型的 Key。比较会去掉首尾空白并忽略 ASCII 大小写；`/`、`_`、空格和 `-` 仍是不同的模型。同一 connection 上的其他 Key 保留各自的允许列表。
- 其余条件都满足时，Gateway 只在已启用、已配置路由、且已授权给这把 Key 的协议里选一条。客户端协议已授权且请求能够转换时优先直通，否则用已保存的首选，再其次是其余已授权协议。选择发生在发送之前，不会为了发现哪条协议已授权而发出请求。发送前仍会重新读取当前授权。

共用**已声明额度池**的 Key 可以共用已保存的普通冷却。`429` 创建的临时冷却只作用于收到它的 Key。名称相同不会自动变成共享池。在同一身份上换 Key 也不会另起一个新池。

`429` 会临时冷却收到它的 Key，然后 Gateway 尝试下一把合格 Key。其他失败按已观测到的范围和重试约束处理，不把任意错误文案当作额度证据。`403` 只在本次请求内换号，不写冷却或 `auth_error`，包括 Kimi 响应。Zen Free 收到任意上游 HTTP 错误时会临时冷却匿名通道，并尝试下一张兼容卡片。OpenCode Go 的结构化 `CreditsError` 401 会换到下一张合格卡片并写入 `auth_error`（仍可能是订阅未生效，不是额度恢复）；续费后重新保存同一个 Key 即可清除。它的 `ModelError`、未知或畸形 401 仍原样返回，因为 OpenCode 也会用 401 表示模型不支持。Custom API 的 `401` 同样换号并写入 `auth_error`。托管账号 Key 验证与 Custom **验证连接** 拿到 401 时仍会记录 `auth_error`。CLI `key ping` 只打印真实上游状态，不写该字段。只有能证明请求尚未发出的 DNS/TCP/TLS 建连失败，才会在同一账号重试一次，流式请求也遵循这一规则。

开启 **对话粘性** 时，匹配的会话 key 会先于基础路由方案尝试。存在 `X-OCG-Conversation-Id` 请求头时优先使用；否则 Gateway 对 system / tools / 首条 user 做指纹。无法生成可用 key 时，严格优先级、全局粘性或轮询按原样执行。

`408`、`5xx` 和无法确认发送或正文结果的失败不重放。首个下游输出之前的不完整或中断流，可在原截止时间内同账号重试一次；输出开始后不重放、不跨账号拼接。所有尝试共用 32 次尝试预算和首输出前的截止时间。未能确认的结果返回 `upstream_outcome_unknown`，因为上游可能已经扣费。所有账号都在冷却或持久化额度恢复状态时，返回 `429` 及最近的已知可重试时间；只有进程内资源等待、没有已知可用时间时返回 `503`。

## 用量估算

5 小时、本周、本月进度条只是 **本地估算**，由 Gateway 实际转发的请求驱动，不是上游账单视图。四类 token 美元单价、窗口额度和模型 `Usage`（官方 **Monthly limit**）都来自当前 OpenCode Go 快照。

- 官方倍率默认按“账号月窗口 / 模型月额度”推导。用户可以为临时活动修改该倍率，新的请求会使用当前持久化值；价格刷新不会在未确认时覆盖它。
- 以账号月窗口 `$60` 为例：`deepseek-v4-pro`、`mimo-v2.5-pro` 和 Grok 4.6 等 `$15` 模型对应 `60 / 15 = 4×`；`deepseek-v4-flash` 等 `$30` 模型对应 `2×`。
- 最后再叠加适用的本地 MiniMax 调整。计算不使用供应商 API 实际价格、人民币或汇率。

日志中的几种特殊情况：

- Chat 流式请求已要求 `include_usage` 后仍没有 usage chunk 时，日志记 `success_no_usage`。
- 快照中没有的模型仍可转发，但会记为 `success_unpriced`，额度消耗显示为空且不进入累计。
- Zen free 模型成功时记 `success` 且 `cost_state=free`：token 会记录，额度消耗显示为免费，不进入 Go 额度累计。
- Custom API 转发记 `cost_state=unknown`，额度消耗为空，不扣任何供应商额度。
- 在快照生成之前记录的成功请求保留原值、标记为“旧口径”，不会回算。
- 手动保存的百分比会成为对应窗口的基线；已完成 Key 或托管账号的官方刷新（手动或自适应同步）会用 OpenCode 官方用量百分比覆盖基线。此后有价格的成功请求继续累加，直到下一次手工校准或官方刷新。真实推理 `429` 不重写用量基线，但在 adapter 支持时可排入稍后的异步官方刷新。
- `outcome_unknown` 表示上游可能已经完成并扣额，但 Gateway 超时或丢失响应；本地额度消耗保持未知，流式重试仅限上文所述的首输出前有界例外。

面板上每条进度条都挨着账号的冷却状态——下一节讲什么才会真正拦住流量。

## 什么真正阻止流量

本地用量条满格或估算积分余额为零，都不会停用账号。校准修改展示基准，不改变路由资格。

上游 `429` 使用上文的临时冷却。已有普通冷却在保存的截止时间到期或显式解除前仍有效。解除普通冷却不会改写持久化额度恢复状态。

不会发送后台或合成推理去清除临时冷却。重启会清除进程内等待，保留的持久化额度回合仍供权威 Go 用量对账。

## Zen Free 模型

Zen Free 是一张不需要 Key 的账号卡，只有一个启用开关。不需要 Free 流量就关掉；启用时，它在账号列表里的位置就是优先级。

在 **供应商** 页点击 **刷新模型目录** 才会请求官方无鉴权 Zen 模型目录。后端只保留 ID 以 `-free` 结尾的模型并持久化成功结果；原始 ID 始终可以作为精确 raw pin。去掉官方 `-free` 后缀后会公布对应 Alias，不要求该短名已经出现在 Go 静态表里。例如 `mimo-v2.5-free` 既可以按原 ID 请求，也可以按 `mimo-v2.5` 请求；共享 Alias 按账号卡顺序选择。仅有 Zen 行的模型（例如 `muse-spark-1.3-contributor-free`）同样公布 `muse-spark-1.3-contributor`。**供应商** 页展示已保存目录与各模型合约。刷新失败或过滤结果为空时，继续使用上一次成功快照。

Free 与 Go 使用**独立冷却窗口**。Zen Free 不发送鉴权头。每次 Free 推理会带上官方 TUI 使用的同一组 OpenCode 客户端身份头（`User-Agent`、`x-opencode-session`、`x-opencode-client`、`x-opencode-request`、`x-opencode-project`），以便会话粘滞和按出口 IP 共享的免费池生效。客户端已提供的 OpenCode 值优先，否则由 Gateway 补齐。促销额度按出口 IP 共享；Free 收到 HTTP 错误、无效 JSON 或明确的错误对象时都会临时冷却匿名通道，而不是切换 Key；`429` 还会遵守有效的 `Retry-After`。确认请求尚未发出的连接失败也按相同规则回退。路由继续尝试顺序中后续兼容卡片。明确请求原始 `-free` ID 时不会悄悄改成其他模型；没有其他兼容路线时由 Gateway 返回本地不可用或限流响应。SSE 已开始输出后无法中途换源。成功的 Free 请求会记录 token，使用 `cost_state=free`，且不计入 Go 额度。Free 为限时促销，请求数据可能用于改进模型，机密内容请谨慎处理。

## OpenRouter Free

OpenRouter 与 OpenRouter Free 是可分别排序的预设连接，都使用 OpenRouter API Key。Free 预设默认通过 Chat Completions 请求 `openrouter/free`，由 OpenRouter 在每次请求时选择具体免费模型。若要指定免费模型，请手动添加目录中确实存在的准确 `:free` ID；不能给任意付费模型加后缀就视为免费。Free 预设不会把混有付费模型的 OpenRouter 全目录刷新成已启用路线。

免费模型收到 HTTP 错误、明确的错误对象或无效 JSON 后，会短暂暂停该模型路线，并尝试相同公开名称下的下一条兼容路线。`429` 则临时冷却收到它的 Key，并遵守有效的 `Retry-After`。这些等待不会把付费余额标为耗尽，也不会冷却 Zen Free。明确请求 `openrouter/free` 或 `:free` 原始模型时仍保持精确绑定；若要切到付费模型，须由你先配置共用的公开别名。Free 请求不扣本地付费 Credit 估算；OCG 将总费用保留为未知，也不提供官方每日额度计量。若请求启用了可能收费的附加功能，以 OpenRouter 账单为准。流式内容一旦开始输出，就不能在中途换源。

### GOAT 余额错误

GOAT 报告余额不足时，是本次请求的上游错误；其正文不会创建持久化额度或余额状态。上下文过长、模型或 reasoning 参数错误等普通 400、413 及其他类似错误同样只在本次请求内处理。只有 `429` 会启动上文的临时冷却及可选异步官方刷新。

MiniMax 上报的缓存计数在 JSON、SSE 和请求记账中保持原始值。Gateway 不会从模型前缀改写这些计数。
