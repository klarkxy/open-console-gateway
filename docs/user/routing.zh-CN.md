# 路由、费用与故障转移

请求从已保存的目的地模型目录解析模型身份，再按全局顺序选择凭据。供应商、凭据、模型的启用状态，协议选择、模型范围和显式 Endpoint 授权共同约束发送。配置异常会明确失败，不回退到重建的旧账号逻辑。每个请求固定模型映射和传输配置，每次发送重新检查当前授权、Key 版本、冷却和已确认的额度恢复；配置变化使旧候选失效，不会悄悄重定向。

**账号** 页从上到下的卡片顺序，再加上每张卡片内的 Key 顺序，就是保存的路由优先级。拖动卡片可整体移动其中的 Key，也可在卡内排序，或把 Key 移到同一供应商的另一张卡片。需要 `A1 → B1 → A2` 时，为 A 再建一张卡片即可，两张 A 卡共用已保存的供应商配置；相邻卡片也不会自动合并。严格优先级、轮询和粘性继续使用原有策略。

### OpenCode Go 新发现的模型

在供应商页刷新模型目录后，明确启用新发现的模型并选择其支持的上游协议。已保存到 Go 目录的模型按有效模型合约处理，即使代码中没有静态别名或协议条目，诊断计划也不会仅因为它是新模型而拒绝请求。未发现、禁用或已删除的模型不会因此获得路由资格，推理时也不会试探协议。本地目录与协议测试不代表真实账号已获得模型权限。

### 已识别额度与临时 429

已确认的按 Key 额度耗尽会把该 Key 变暗并跳过路由。用量到 100%、未知或失败都不会据此推断耗尽。这项耗尽状态不会复制到已声明额度池的其他成员。已保存的普通冷却仍然有效，Zen Free 使用独立的共享通道恢复。

下列错误视为已识别额度：

- Kimi：明确写出 5 小时、周或月窗口的 `403`。
- OpenCode Go：仅在明确给出 5 小时、周或月窗口时。结构化 `CreditsError` 401 仍可能是订阅未生效，继续走既有 `auth_error` 路径。
- GOAT：严格的套餐窗口错误，即使没有重置截止时间；以及已知的余额不足错误。
- MiniMax：`1008` 与 `2056`。
- 可配置 HTTP：结构化的 `insufficient_quota` 或 `insufficient_balance`。

无法识别的临时 `429` 不证明额度耗尽。没有可用重试约束时，只在本次请求排除该账号，保留原本健康的粘性目标，不编造五分钟账号冷却。`Retry-After` 约束对应的端点和模型；若伴随已确认的按 Key 耗尽，则单独约束该 Key，与额度重置同时适用。它不会被显示为额度重置时间，也不会把该 Key 的耗尽传播给其他成员。

已知重置等到点。未知窗口先等 15 分钟，再 1 小时，再 6 小时（封顶）；只有再次证明是额度错误才会升阶。到期后，下一次本来就会选中这把 Key 的请求就是唯一试探。Gateway 不会另发探测、不会跑调度器，也不会把其他流量挂起等待验证。手动重试只让 Key 重新具备资格。只有完整成功的 JSON 或 SSE 会恢复（即使没有 usage）。超时、取消或 5xx 保留耗尽、释放这次试探，至少 15 分钟后可再试，且不升高未知窗口阶梯。旧 Key 或旧耗尽回合的成功不能清掉当前状态。

## 账号选择与切换

在**别名**页展开模型即可读取只读路由解释：解析后的映射、合格连接与 Key、上游协议、全局顺序、结构化排除原因，以及基础策略当前预计首选。预览不会发送上游请求、解密 Key、写冷却、额度恢复或日志，也不会推进粘性、轮询或额度试探状态。它不模拟对话绑定、本次重试排除、快照后的状态变化或上游结果，因此解释的是观察时的基础策略，不是送达保证。

账号按 **列表顺序** 尝试，你可以在账号页拖动排序并持久保存。选择器会跳过以下对象：

- 已禁用账号；
- 处于冷却中的账号；
- 已确认额度耗尽的 Key，除非到期后这把 Key 正好是下一次正常选择的唯一试探；
- 已经在本次请求里失败过的账号（例如拿到 `429`）；
- 已保存供应商合约对该解析模型没有 effective 启用上游协议的账号；
- 推理绑定已停用、或绑定 `modelScope` 不包含当前请求的公开/路由模型的 Key。同一 connection 上的其他 Key 保留各自的允许列表。

共用**已声明额度池**的 Key 可以共用已保存的普通冷却。已确认的额度耗尽只作用于那把 Key，不会扇出。名称相同不会自动变成共享池。在同一身份上换 Key 也不会另起一个新池。

已识别的额度错误会按 Key 持久化恢复状态，然后尝试下一把 Key。其他失败按已观测到的范围和重试约束处理，不把任意错误文案当作额度证据。普通 `403` 不写冷却、直接换号；Kimi 明确套餐窗口的 `403` 走额度恢复，不是这条普通路径。Zen Free 的 `401` 原样返回。OpenCode Go 的结构化 `CreditsError` 401 会换到下一张合格卡片并写入 `auth_error`（仍可能是订阅未生效，不是额度恢复）；续费后重新保存同一个 Key 即可清除。它的 `ModelError`、未知或畸形 401 仍原样返回，因为 OpenCode 也会用 401 表示模型不支持。Custom API 的 `401` 同样换号并写入 `auth_error`。托管账号 Key 验证与 Custom **验证连接** 拿到 401 时仍会记录 `auth_error`。CLI `key ping` 只打印真实上游状态，不写该字段。只有能证明请求尚未发出的 DNS/TCP/TLS 建连失败，才会在同一账号重试一次，流式请求也遵循这一规则。

开启 **对话粘性** 时，匹配的会话 key 会先于基础路由方案尝试。存在 `X-OCG-Conversation-Id` 请求头时优先使用；否则 Gateway 对 system / tools / 首条 user 做指纹。无法生成可用 key 时，严格优先级、全局粘性或轮询按原样执行。

`408`、`5xx` 和无法确认发送或正文结果的失败不重放。首个下游输出之前的不完整或中断流，可在原截止时间内同账号重试一次；输出开始后不重放、不跨账号拼接。所有尝试共用 32 次尝试预算和首输出前的截止时间。未能确认的结果返回 `upstream_outcome_unknown`，因为上游可能已经扣费。所有账号都在冷却或额度耗尽时，返回 `429` 及最近的已知可重试时间；只有进程内资源等待、没有已知额度重置时返回 `503`。

## 用量估算

5 小时、本周、本月进度条只是 **本地估算**，由 Gateway 实际转发的请求驱动，不是上游账单视图。四类 token 美元单价、窗口额度和模型 `Usage`（官方 **Monthly limit**）都来自当前 OpenCode Go 快照。

- 官方倍率默认按“账号月窗口 / 模型月额度”推导。用户可以为临时活动修改该倍率，新的请求会使用当前持久化值；价格刷新不会在未确认时覆盖它。
- 以账号月窗口 `$60` 为例：`deepseek-v4-pro`、`mimo-v2.5-pro` 和 Grok 4.6 等 `$15` 模型对应 `60 / 15 = 4×`；`deepseek-v4-flash` 等 `$30` 模型对应 `2×`。
- 最后再叠加适用的本地 MiniMax 调整。计算不使用供应商 API 实际价格、人民币或汇率。

日志中的几种特殊情况：

- Chat 流式请求已要求 `include_usage` 后仍没有 usage chunk 时，日志记 `success_no_usage`。
- 快照中没有的模型仍可转发，但会记为 `success_unpriced`，额度消耗显示为空且不进入累计。
- Zen free 模型成功时记 `success` 且 `cost_state=free`：token 会记录，额度消耗显示为免费，不进入 Go 额度累计。
- Custom API 转发记 `cost_state=unknown`，额度消耗为空，不扣任何供应商额度。
- 在快照生成之前记录的成功请求保留原值、标记为“旧口径”，不会回算。
- 手动保存的百分比会成为对应窗口的基线；已完成 Key 或托管账号的官方刷新（手动或自适应同步）会用 OpenCode 官方用量百分比覆盖基线。此后有价格的成功请求继续累加，直到下一次手工校准或官方刷新。真实推理 `429` 按范围写入恢复状态，或在已识别为额度时写入按 Key 恢复；不重写用量基线，但临时 429 仍会调度稍后的官方对账。
- `outcome_unknown` 表示上游可能已经完成并扣额，但 Gateway 超时或丢失响应；本地额度消耗保持未知，流式重试仅限上文所述的首输出前有界例外。

面板上每条进度条都挨着账号的冷却状态——下一节讲什么才会真正拦住流量。

## 什么真正阻止流量

本地用量条满格或估算积分余额为零，都不会停用账号。校准修改展示基准，不改变路由资格。

已确认的按 Key 耗尽按上文的持久化等待和单次试探规则恢复。已有普通冷却在保存的截止时间到期或显式解除前仍有效，对应进度条在冷却期间显示 100%。解除普通冷却不会清除按 Key 的额度恢复。

其他已观测到的端点限制和匿名 Free 耗尽使用进程内等待。恢复时间未知时，约 30 秒加小幅抖动后，可由真实客户端请求承担一次试探；失败重探逐步退避至最长 300 秒，不发送后台或合成推理。完整且协议有效的响应只能清除自己的试探租约；畸形 200 JSON、不完整流和取消均不证明恢复。重启会清除这些进程内等待，持久化的按 Key 额度状态仍保留。

## Zen Free 模型

Zen Free 是一张不需要 Key 的账号卡，只有一个启用开关。不需要 Free 流量就关掉；启用时，它在账号列表里的位置就是优先级。

在 **供应商** 页点击 **刷新模型目录** 才会请求官方无鉴权 Zen 模型目录。后端只保留 ID 以 `-free` 结尾的模型并持久化成功结果；原始 ID 始终可以作为精确 raw pin。去掉官方 `-free` 后缀后会公布对应 Alias，不要求该短名已经出现在 Go 静态表里。例如 `mimo-v2.5-free` 既可以按原 ID 请求，也可以按 `mimo-v2.5` 请求；共享 Alias 按账号卡顺序选择。仅有 Zen 行的模型（例如 `muse-spark-1.3-contributor-free`）同样公布 `muse-spark-1.3-contributor`。**供应商** 页展示已保存目录与各模型合约。刷新失败或过滤结果为空时，继续使用上一次成功快照。

Free 与 Go 使用**独立冷却窗口**。Zen Free 不发送鉴权头。每次 Free 推理会带上官方 TUI 使用的同一组 OpenCode 客户端身份头（`User-Agent`、`x-opencode-session`、`x-opencode-client`、`x-opencode-request`、`x-opencode-project`），以便会话粘滞和按出口 IP 共享的免费池生效。客户端已提供的 OpenCode 值优先，否则由 Gateway 补齐。促销额度按出口 IP 共享；Free `429` 限制匿名 Free 通道，而不是切换 Key。已知重置会持久化，恢复未知则进入同一套本地单飞等待。路由继续尝试顺序中后续兼容卡片；仅有 Free 映射且没有已知重置时，返回本地不可用，而不是虚构额度截止时间。成功的 Free 请求会记录 token，使用 `cost_state=free`，且不计入 Go 额度。Free 为限时促销，请求数据可能用于改进模型，机密内容请谨慎处理。

### GOAT 未给重置时间的余额不足

GOAT 返回准确的 `400` / `BAD_REQUEST` / `invalid_request_error` 余额不足声明时，这是账号级额度拒绝，不是提示词格式错误。当前请求会尝试下一个合格账号，每个账号至多一次。即使上游没有重置时间，该 Key 也会持久化为额度耗尽（`insufficient_balance`）；不改启用开关，也不标记为鉴权失败。恢复遵循上文的按 Key 等待与单次试探。上下文过长、模型或 reasoning 参数错误等普通 400、413 及其他供应商无法识别的相似文案仍不会进入这条路径。
