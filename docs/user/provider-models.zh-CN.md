# 管理供应商的单个模型

模型表分页显示。搜索和**仅看已启用**针对完整目录；选择全部匹配模型时包含其他页的结果。编辑器在保存前读取完整配置与凭据授权。

在**供应商**页选择内置供应商或可配置 HTTP 供应商（包括从预设创建的 HTTP 供应商和旧版 Custom API 连接）。各供应商的模型表统一使用**添加模型**、一个模型名/别名搜索框和**仅看已启用**。编辑模型时，直接点击该行**操作**列的铅笔按钮。即使从未刷新过目录、当前目录为空，也能手动添加。原有表格继续提供单模型删除和勾选后批量删除。

## 内置供应商

MiniMax CN Token Plan、Kimi Code CN、OpenCode Go、Zen Free、Command Code GOAT 和 Ollama Cloud 共用完整的新增/编辑表单：上游模型 ID、对外模型名（可调用别名）、上游协议、首选协议和允许路由。空目录也能新增。每个内置上游模型对应一条映射；修改别名请编辑已有行。HTTP 供应商仍允许多个别名指向同一上游。

别名真正参与客户端模型列表和路由，上游收到的仍是原始模型 ID。自定义别名替换该模型原来自动生成的对外名称；原始上游 ID 沿用已有的精确匹配和歧义检查。不会改变其他供应商使用相同公开名称的映射。

手动新增的内置模型允许路由默认关闭；目录刷新按供应商的文档证据处理，并保留已保存的 ForceOff。协议只能选内置适配器支持的范围；连接地址和鉴权方式仍固定。保存不发送上游请求、不新增 Key 授权或扩大 Key 的模型范围。若 Key 原先只授权旧别名，重命名后需自行检查其范围。

保存的别名、协议、首选协议和开关在重启后保留。**刷新模型目录**会按官方返回重建目录：仍在目录中的上游模型保留以上设置；新发现的 MiniMax CN、Kimi CN 与 GOAT 别名从完整已保存目录生成，未返回的手动模型可能被移除。Kimi 的 `kimi-for-coding` 与 `kimi-for-coding-highspeed` ID 保持原样。只手动建立的目录标为“手动添加”，不会伪造官方刷新时间。

## 模型字段

- **上游模型 ID**：真正发送给供应商的模型标识，必填。
- **对外模型名**：客户端在 `model` 字段中使用的可调用别名，不只是显示名称。内置目录行的自动名称来自完整已保存目录归一化后的最后一个斜杠分段；填写明确名称会替换该自动名称。同一供应商内，忽略首尾空白和 ASCII 字母大小写后不能重名；不同别名可以指向同一个上游模型。
- **上游协议**：选择该模型允许使用的已配置上游路由。**首选协议**必须包含在这些选择中。这不是客户端入口协议的拒绝列表，网关原有的协议转换仍然有效。HTTP 供应商新增或修改协议地址应进入**编辑连接**，而不是在单模型表单中修改。
- **允许路由**：启用该模型映射。启用时至少选择一种协议；停用不会删除模型。能否实际调用仍取决于连接、Key、模型范围、授权和上游状态。

已有的逐模型上游地址覆盖会原样保留，并以只读方式显示；此时只能选择该覆盖所使用的协议。修改别名会替换原行，不额外保留旧别名。跨供应商的名称冲突仍按网关现有规则处理，歧义名称不会被任意路由。

## 保存与删除

保存通过带 CAS 校验的 V4 模型编辑接口（内置供应商）或连接 PATCH（HTTP）完成，保留其他模型的映射、启用状态、协议选择，以及供应商已有的地址配置。不会为 Key 新增授权、扩大模型范围、自动发现模型或发送可能付费的测试请求。模型映射变化时，仍执行后端原有的验证状态失效规则。

打开表单时会捕获配置版本。其他窗口修改配置或服务重启后，旧表单不能静默覆盖新状态。过期提示中的**重试**会重新载入最新已保存字段；重新填写修改内容后再保存，不会自动重放旧请求。

使用表格中的删除操作可移除一行，也可勾选后批量删除。原有目录删除接口允许删掉最后一个模型。删除只影响本地目录，之后手动刷新时可能再次发现相同上游 ID；HTTP 模型重新发现后默认启用。需要在刷新后保留关闭状态时，应停用该行而不是删除。

## 支持范围

内置供应商可编辑模型映射及协议，但封闭适配器、连接地址和鉴权方式保持原样。CPA 仍由外部集成管理目录，不提供手动新增。少数仍保留多个隐式协议的旧 HTTP 连接，需要先在**编辑连接**中配置明确的协议路由；单模型编辑器不会静默把这些连接压缩成单协议。
