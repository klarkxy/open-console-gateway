# New API 与 Sub2API 账号

站点若部署在 `/chat` 等子路径，填写的站点根地址可以是 `/chat` 或 `/chat/v1`。添加和刷新 Key 时会访问 `/chat/v1/models`；Chat 推理访问 `/chat/v1/chat/completions`，Responses 与 Messages 也走对应路径。解除关联后，如果原 Custom 连接已无 Key，且路由与模型映射均未改变，Key 会回到原连接；共享或已编辑的连接保持原样。

每个站点是**一个账号**，下面可以有多把 Key。**添加 Key** 只填写名称和 Key。保存时按该 Key 向站点拉取可用模型，再完成关联。New API 在已保存管理凭证后，可用**从站点导入 Key**：列出远端令牌、读取完整 Key、在本地创建 Custom Key 并关联。本地已有、已停用、或无法读取完整 Key / 模型的令牌会跳过。New API 与 Sub2API 自己会做 Chat Completions、Messages、Responses 之间的协议转换，因此 OCG 不为每把 Key 选择协议，也不打开供应商页的模型矩阵。创建成功但关联失败时，会明确显示 Key 已存在，重试只执行关联。刷新页面后，已创建的独立 Key 仍可通过关联已有 Key 继续处理。创建结果不确定时，应先核对账号列表，不直接重复创建。

**New API** 和 **Sub2API** 是平台类型，不是各自只能添加一个的供应商。每个站点或用户账号分别添加一个具名实例；多个 New API 实例、多个 Sub2API 实例可以同时存在。每个实例有独立身份、站点地址、凭证、关联 Key 和观察数据。刷新、编辑或删除一个实例不会操作同类型的其他实例。

在**账号**页点击**新增账号**，从**平台账号**分组选择 **New API** 或 **Sub2API**，再填写站点地址和名称。该站点在账号列表里显示为一张可排序卡片。拖动这张卡片决定它在全局路由中的位置；卡片内的 Key 用上移/下移决定彼此之间的失败切换顺序。对某把 Key 点**获取模型**（或**获取全部模型**），会按这把 Key 调用站点的 `GET /v1/models` 并保存它自己的列表。两把 Key 出现同一对外名称是叠加，不是冲突：带鉴权的 `GET /v1/models` 只列出一次，请求按 Key 顺序失败切换。请给每把 Key 起能区分的名称（例如「Codex 稳定」和「Codex Pro」）；刷新后每把 Key 会标出站点分组、与本地名称不同时的令牌名，以及这把 Key 可路由的模型数。点击模型数会在账号页打开该 Key 的模型列表；New API 与 Sub2API 站点不会出现在**供应商**页。

填写站点根地址；部署在子路径时保留该路径。平台类型和地址创建后固定。你可以明确关联现有 Custom API Key，也可以在站点卡片里添加 Key；New API 在保存管理凭证后还可以从站点导入 Key。导入的 Key 秘密与手动添加的一样只存在本地，不会通过界面接口返回。手动关联不能证明远端归属或模型调用权限。关联 Key 记为对平台账号的已声明（未验证）关系。关联期间推理使用站点根地址，并把客户端的 Chat、Messages 或 Responses 原样交给上游；Gemini 客户端仍转换为 Chat Completions。

可选的用户凭证用于读取用户范围的数据。New API 分别填写个人设置里的数字用户 ID，以及「个人设置 → 安全设置 → 系统访问令牌」，不要填令牌页的推理 Key。用户 ID 会作为 `New-Api-User` 发给仍要求该请求头的站点；较新的 New API 会忽略它。Sub2API 填写登录用户的访问令牌。该凭证与推理 Key 分开保存，不通过界面接口返回，也不进入迁移包。不填写时仍可读取 Key 范围的数据。用户凭证过期不会禁用推理；清除凭证会清除依赖它的缓存观察值。

导入成功提示、Key 行和模型列表均按去重后的对外模型名统计。同一模型支持 Chat、Messages、Responses 三种协议时，仍只计为一个模型。

## 刷新和查看数据

数据需要手动刷新。父账号卡展示站点的**余额**、**本月**和**历史**。它们来自站点钱包和消费日志，不是本地价格，也不是单次请求费用。官网 API 卡只显示剩余余额。余额和历史来自站点钱包；本月是当前 UTC 月的站点消费日志合计（可选接口，没有就显示 —）。父卡片的**刷新**读取站点钱包。每把关联 Key 行可在启用开关旁显示自己的剩余；该行的**刷新**只读取这把 Key 的剩余额度，不读取站点钱包。钱包、订阅和 Key 额度属于不同范围，不能相加。

未填写可选用户凭证时，父账号钱包保持未知；请刷新各把 Key 以读取该 Key 的剩余额度。缺少管理凭证不是卡片错误，站点卡上不常驻错误条。刷新时若观测无法进行，只会弹出一次提示。New API 的数量以站点原生 quota 点保存，并在 `GET /api/status` 返回正的 `quota_per_unit`（站点自己的点数兑美元比率）时换算为美元。没有该比率时保持 `quota` 单位。

New API 支持钱包和订阅计费、固定及自动分组、扣费偏好。Sub2API 当前余额来自用户资料，或来自 Key 的 `/v1/usage` 在明确提供 `balance` 字段时的观测值。明确的模型权限或通过 Key 认证的 `GET /v1/models` 决定这把 Key 可以路由的模型。刷新读取模型、用量、余额和分组。它不会拉取价格表，也不会估算请求费用，更不会因此改变可路由模型。

没有记录到的费用保持未知，不会显示成零或免费。新快照如果没有价格，以前保存的价格仍留在旧快照里，不会用来给新请求定价。之后的刷新不会重算旧记录。站点余额观测不能证明某一次请求从钱包扣了多少。

## 修改与迁移

关联 Key 的端点由父账号管理。解除关联会保留 Key、已生成的端点和模型配置。删除父账号前，需要先解除全部子 Key 的关联或删除子 Key；删除父账号不会连带删除 Key。

导出使用当前 payload，以目的地与凭据为权威：父账号定义、关联、管理密钥和平台 extras 与推理 Key 一起只存在加密信封内。合并导入时，若包中没有 CPA 或平台 observer key，会保留目标已有 management key。导入后草稿连接在完成前不会进入路由。导入接受 V4 至当前导出版本。导入分组在获得新证据前保持未验证。同一父账号 ID 对应不同平台或站点地址时，整笔导入失败并回滚。当前版本见[升级与备份](upgrade-backup.zh-CN.md)。

升级前备份完整数据目录。回滚需要恢复完整备份，不要用旧版程序打开已迁移数据库。详见[存储与迁移](../maintainer/storage-migration.zh-CN.md)。

读取器固定基线为 New API `71c1fd7caad738db4d13aabbf28eeadb293d0cfe` 和 Sub2API `772a0382f079676983c06f24b0d41e09139a8462`。旧版及分叉可能缺失或修改相关接口；观察数据不可用并不等于推理失败。

## 刷新隔离与分批导入

父账号和每把 Key 的**刷新**只更新观察数据，不再二次发现模型或改写已保存的模型路由。需要修改模型配置时，明确使用**获取模型**。模型发现结果被截断时保留原配置；空列表和获取失败同样不替换原配置。

Key 刷新只报告这把 Key 的错误，不再显示父账号的旧错误。Sub2API Key 刷新不读取管理用户的钱包、订阅或可用分组，也不会查询模型广场价格。通过 Key 自身认证得到的余额保留在该 Key 范围。

某个接口失败时，成功分项仍会保存，只有失败来源的数据保留旧值。失败的这次尝试不会给保留的记录续上新的有效期。快照时间表示最近一次尝试，不表示每条保留的数据都在该时刻更新。父账号观察刷新不再使进行中的子 Key 刷新冲突；站点地址、管理凭证、关联及推理 Key 的变化仍使旧结果失效。

New API 每次最多复制 50 条远端记录，并明确返回 `nextPage`。即使整批都是停用或已导入的 Key，也可能仍有下一批。在当前会话再次点击**从站点导入 Key**即可继续；全部完成后，下一次从第一页重新扫描。刷新页面或退出登录也会重置游标。这是有界复制，不是远端同步；远端清单并发变化后应重新扫描。重复密钥只在所选平台实例内检查，已导入的 Key 不再重复发现模型。
