# v2.8.0

[简体中文](v2.8.0.zh-CN.md)

## Upgrade

Stop processes using the data directory and back up the whole directory before upgrading. A v2.7.0 database migrates from schema v64 to v66: v65 adds operation receipts and a logical-request grouping index; v66 stores GOAT plan reset windows per Key. The v65 migration creates a verified SQLite backup before changing an existing database. Older binaries refuse v66; restore the complete pre-upgrade data directory to roll back. See the [migration guide](../maintainer/storage-migration.md).

Portable exports now use payload V12. V4–V11 imports remain supported; older versions cannot import V12. Keep an earlier export when an older reader is needed.

Live reference pricing, price multipliers and price-based debit estimates are retired. Existing historical costs and credit receipts remain stored; opening the database does not settle or reprice them. Supplier balance and quota observations remain available. Retired dashboard pricing routes are removed.

This is a minor release under the product version policy because it adds log-query interfaces and persistent operation records, alongside the fixes below.

## Changes

- Separate logical requests, operation receipts and program diagnostics. The Logs page groups attempts under each request and shows operations separately. Native program logs rotate under the data directory with credential redaction and private permissions; Docker keeps stderr logging.
- Publish one atomic request-preparation snapshot so requests do not wait on repeated control-plane reads. Preserve final credential checks before sending upstream.
- Respect GOAT Key-local five-hour, weekly and monthly reset windows, including restart and portable transfer. Manual recovery and actual Key replacement clear only the selected Key's local windows.
- Cache billing snapshots in Rust and let quota refresh proceed independently of slower balance reads. Guard late responses across logout, account replacement and view disposal.
- Repair dashboard save, delete, revalidation and KeepAlive lifecycles across Accounts, Providers, Keys, Aliases, Settings and CPA. Keep confirmed writes visible when follow-up reads fail.
- Show alias mapping capabilities and link to capability declarations. Fill missing model metadata from models.dev per field and retain configured reasoning preferences.
- Bound request-debug captures and program-log files, reject linked paths, and preserve credential redaction. Limit development watched trees and preserve Windows executable paths.

## Verification

Local release preflight, the Web production build, both dashboard contract checks and the CLI build passed on Windows with Node.js 22.23.3. The isolated local Gateway Lab passed all 98 scenarios with zero remote calls and verified process/port cleanup. Its 87 unit tests also passed. The acceptance assertion for absent prices now checks unknown cost, null amounts and the correct account attribution after pricing retirement.

The final commit must pass main Quality before tagging. The release workflow verifies Windows, macOS and Linux packages and updater signatures before publication; the separate container workflow verifies both architectures and anonymous pulls.

No real supplier calls or interactive macOS/Linux desktop sessions are part of this preparation. Windows installers have no Authenticode signature; macOS apps use ad-hoc signing and are not notarized.
