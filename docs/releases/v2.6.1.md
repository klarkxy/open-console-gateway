# v2.6.1

[简体中文](v2.6.1.zh-CN.md)

## Upgrade

Stop processes using the data directory and back up the whole directory before upgrading. This release does not change the database schema. The new `api_key` authentication value can be saved on configurable HTTP connections; v2.6.0 does not understand that value. If you need to roll back after saving such a connection, restore the pre-upgrade backup.

Updating OCG does not rewrite existing connections. To adopt newer preset routes, open the connection editor, choose **Adopt preset protocols**, review addresses and Key grants, and save.

## Changes

- Recheck all 55 supplier presets against operator documentation and add confirmed Chat Completions, Responses, and Messages routes. The chooser shows the route set and authentication methods. Azure OpenAI and Bedrock fill additional routes after a matching resource or regional URL is entered. Azure static API Keys use the `api-key` header. See the [preset and source table](https://github.com/klarkxy/open-console-gateway/blob/v2.6.1/docs/user/provider-presets.md).
- Seed GOAT's first model-catalog snapshot from the plan's included-model list. Models first discovered on later refreshes use the normal enabled default; saved operator switches remain authoritative.
- Temporarily cool a rejected Zen Free channel and a rejected OpenRouter free-model route, then try another compatible route. OpenRouter Free does not turn paid catalog models into enabled free routes or debit the local paid Credit estimate.

## Verification

Local Windows checks passed: `pnpm run test` (772 Web tests, tooling checks, and the full Rust workspace), design lint, V3/V4 contract checks, Rust formatting, Compose validation, `release:check`, and the Windows installer/CLI build. Both release files match `SHA256SUMS`; the packaged CLI reports `2.6.1`. Gateway Lab ran against that packaged CLI with 98 PASS, 0 FAIL/UNSUPPORTED/NOT_RUN, `remoteCalls=0`, and verified process/listener cleanup. Release CI separately builds and verifies signed updater payloads across supported platforms before publication.

No real supplier credentials were used in local checks. Interactive installer, real-client, and other-platform desktop checks were not run locally. Some Messages URLs follow an operator's documented SDK base URL and the standard `/v1/messages` path; model and plan availability still depend on the upstream account.

Updater payloads carry Tauri minisign signatures. Windows installers have no Authenticode signature; macOS apps use ad-hoc signing and are not notarized.
