# v2.9.0

[English](v2.9.0.md)

## 升级

没有数据库迁移。schema 仍是 v66，便携导出仍是 payload V12，v2.8.0 的数据目录可以直接打开。备份与回退见[升级与备份指南](../user/upgrade-backup.zh-CN.md)。

本次升级 OCG 之后，在 **应用 → DSH** 安装或替换一次插件，并按提示重启 DSH。只更新网关不会替换 DSH 里已经加载的插件。

未知或无效的协议配置保持失败关闭：这些名称不会出现在带鉴权的 `GET /v1/models` 中，DSH 的精确 resolve 与 prepare 仍返回 `INVALID_CONFIG`。

本次除下列修复外，还发布按模型协议配置与原生不透明历史绑定，按产品版本规则为次版本。

## 变更

- 带鉴权的 `GET /v1/models` 发布推导出的按模型协议配置：`ocg.schemaVersion` 2，含 `protocols.preferred` 与 `protocols.supported`。没有有效配置的名称不会出现。该配置不写入元数据记录。
- 把原生不透明多轮历史绑定到观察到的路由（`ocg-replay-v1`）。错误路由、未标记且非空的不透明历史、未知版本或畸形标记会在发出 HTTP 之前拒绝。普通文本和工具仍可移植。
- 无法保真的转换会被拒绝，包括原生不透明思考和没有忠实形式的参数。
- DSH 插件按模型的首选协议选择 `openai-completions`、`openai-responses` 或 `anthropic-messages`，并应用已声明的推理档位，不会把 `reasoning: true` 变成 Messages 预算。
- Kimi Code、MiniMax Code 和 ZCode 按该首选协议把模型分到 `ocg-chat`、`ocg-responses` 和 `ocg-messages`。Codex 仍使用 `model_providers.ocg`。切换协议分组不会迁移旧会话。
- 工具载荷等数据键下的普通 JSON 对象按普通数据处理，不当作原生加密推理。
- 每次列出或解析只构建一份目录快照和一份别名索引，不再为每个名称重建表。
- DSH 目录按需加载，超时与其他失败分开分类，取消一名等待者不会中断共享刷新。
- 重装时，已有文件仍匹配则恢复不完整的 DSH 插件缓存。
- 更新滞后于上述行为的测试。

## 验证

`pnpm run release:check`（unsigned local）、`pnpm run build:web`、`cargo fmt --check`、`ocg-core` 与 `ocg-gateway` 的全 target Clippy `-D warnings`，以及 `--locked` CLI 构建均通过。该 CLI 的 `--version` 为 `2.9.0`。

本地 Gateway Lab 为 98 PASS、0 FAIL / UNSUPPORTED / NOT_RUN，`remoteCalls=0`，进程和端口 `cleanup.verified=true`。Responses、Chat Completions、Messages 的元数据检查均返回 HTTP 200，普通元数据和答案保持原样，`remoteCalls=0` 且 `cleanup=true`。DSH 0.2.0-rc.2 与 pi-ai 0.87.1 上，三种原生 API、两轮工具、原生不透明还原、wrong-tuple / wrong-domain 零 HTTP，以及交错脱敏压力全部通过，`gateway.cleanup=true`。报告：`.artifacts/gateway-lab/20261005T141014Z-15fcb784/report.json`、`.artifacts/acceptance/final-metadata-report.json`、`.artifacts/acceptance/final-native-sdk-report.json`。本机 DSH 使用已确认。

打标签前，最终提交必须通过 main Quality。打标签后，发布工作流在正式发布前验证 Windows、macOS、Linux 安装包及更新签名；独立容器工作流验证两种架构和匿名拉取。

本次准备不包含真实供应商调用，也不包含 macOS/Linux 桌面交互。Windows 安装包没有 Authenticode 签名；macOS 应用使用 ad-hoc 签名，未公证。
