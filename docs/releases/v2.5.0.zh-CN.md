# v2.5.0

[English](v2.5.0.md)

## 升级

升级前停止使用数据目录的进程，并备份整个目录。数据库将迁移到 schema v62，旧版程序不能打开升级后的数据库；回滚需要恢复升级前备份。

面板接口现使用 `/dashboard/api/v4`。V3 返回 HTTP 410，调用面板接口的集成须迁移到 V4。推理接口和现有客户端 Key 保持可用。节点备份导出 V10，支持导入 V4–V10。

## 变化

- 在供应商页管理共用 HTTP 连接配置，在账号页管理独立 Key。同一供应商可使用多张路由卡片，实现 A1 → B1 → A2 等顺序，无需复制供应商配置。HTTP 模型在展示和路由时保留空格与分隔符的区别。
- 从别名页查看路由解释，包括凭据顺序、协议选择和账号被排除的原因。
- 按 Key 持久化已确认的额度耗尽，到期后由一次真实请求试探恢复。临时端点限制和 `Retry-After` 与额度重置证据分开处理，所有回退尝试共用请求预算。目录刷新不会使已观察到的共享 Free 限额证据失效。
- 账号计费视图展示周期额度、官方现金余额和个人积分估算。可配置 HTTP 账号支持按模型积分价格、月度发放、有到期时间的加油包和余额校准；估算不影响路由资格。平台关联 Key 保留现有站点计费视图，已认证的 New API Key 刷新价格无需查询站点钱包。
- 修改价格和迁移备份时保留个人余额。流式重复完成不重复扣减；明确被拒绝的请求按零结算，缺少用量和无法确认的结果保留未知。
- 并发 CLI 命令打开同一数据库，不再提前结束活跃请求的结算记录。退出登录、账号变化或离开视图后，旧用量响应不能覆盖当前数据。
- 保留 [#73](https://github.com/klarkxy/open-console-gateway/pull/73) 的上游失败与恢复修复，包括 GOAT 余额不足处理、按范围等待，以及首个下游输出前的有界流式重试。

## 验证

Windows 11（build 26200）本地验证通过 700 项前端测试、91 项发布工具测试、58 项 Gateway Lab 测试夹具测试及前端构建。最终核心单元测试通过 1,250 项（跳过七项需主动启用的测试），并对路由、恢复、请求预算、备份和 V4 目标进行了集成验证。另有两项公开价格源联网检查通过。

全工作区严格静态检查、V3/V4 契约检查及最终 CLI 构建通过。完整本地 Gateway Lab 验证通过，远端调用为零，进程与端口清理已确认。此前一次清理超过等待时限；确认进程退出和端口关闭后，按相同标准完整复跑通过。

在隔离的 Windows 面板会话中试用了账号积分设置、加油包、请求日志和路由解释，并以模拟上游请求确认配置的扣费。未采集 Chrome 运行时版本。正式发布流程会重新运行工作区测试、静态检查和 API 契约检查，构建三个平台，并在发布前验证更新包签名。

本地验证不包含真实付费供应商请求、Key 剪贴板内容、安装/升级/卸载和自启动人工操作、macOS/Linux 桌面操作、浏览器配置持久化、SmartScreen，以及真实托管注册和付款流程。

更新包使用 Tauri minisign 签名。Windows 安装器无 Authenticode 签名；macOS 应用使用 ad-hoc 签名，未公证。
