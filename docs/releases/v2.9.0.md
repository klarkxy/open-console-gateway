# v2.9.0

[简体中文](v2.9.0.zh-CN.md)

## Upgrade

No database migration. The schema stays at v66, portable export stays payload V12, and a v2.8.0 data directory opens directly. Backup and rollback are in the [upgrade and backup guide](../user/upgrade-backup.md).

After this OCG upgrade, install or replace the plugin once in **Applications → DSH**, then restart DSH if prompted. Updating the gateway alone does not replace a plugin already loaded in DSH.

Unknown or invalid protocol profiles stay fail-closed: those names are omitted from authenticated `GET /v1/models`, and DSH exact resolve and prepare stay `INVALID_CONFIG`.

This is a minor release under the product version policy because it publishes the per-model protocol profile and native opaque replay binding, alongside the changes below.

## Changes

- Publish a derived per-model protocol profile on authenticated `GET /v1/models`: `ocg.schemaVersion` 2 with `protocols.preferred` and `protocols.supported`. A name without a valid profile is omitted. The profile is not stored with the metadata record.
- Bind native opaque multi-turn history to the observed route (`ocg-replay-v1`) and reject a wrong route, unmarked nonempty opaque history, unknown version, or malformed marker before HTTP. Ordinary text and tools stay portable.
- Reject conversion that cannot preserve required fields, including native opaque thinking and parameters with no faithful form.
- Select DSH native APIs (`openai-completions`, `openai-responses`, or `anthropic-messages`) from the model's preferred protocol. Apply declared reasoning efforts; `reasoning: true` does not become a Messages budget.
- Group Kimi Code, MiniMax Code, and ZCode models by that preferred protocol into `ocg-chat`, `ocg-responses`, and `ocg-messages`. Codex stays on `model_providers.ocg`. Switching a protocol group does not migrate an old conversation.
- Treat ordinary JSON objects under tool payloads and similar data keys as ordinary data, not native encrypted reasoning.
- Build one catalog snapshot and one alias index per list or resolve, instead of rebuilding the table for every name.
- Load the DSH catalog on demand, classify timeouts separately from other failures, and keep one waiter's cancel from taking down a shared refresh.
- Recover an incomplete DSH plugin cache on reinstall when the files already present still match.
- Update tests that lagged those behaviors.
