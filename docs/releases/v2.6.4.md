# v2.6.4

[简体中文](v2.6.4.zh-CN.md)

## Upgrade

Stop processes using the data directory and back up the whole directory before upgrading. Schema v64 renames preset-generated `<preset-id>/<upstream-id>` public model names to their last upstream-ID segment when there is no collision. Update clients that request a renamed model. Exact upstream IDs, manually named mappings and historical logs remain unchanged. Older binaries cannot open schema v64; restore the pre-upgrade directory to roll back. See the [migration guide](../maintainer/storage-migration.md#schema-v64--preset-public-model-names).

After updating OCG, install/replace its plugin once in **Applications → DSH**, then reload DSH to receive the model metadata changes.

## Changes

- Finish account and Provider saves and deletions as soon as the service confirms them; refresh dependent lists in the background. Prevent late observations from restoring deleted accounts, expose local deletion for linked Keys, and allow removal of empty configurable HTTP account groups.
- Queue account refreshes, separate platform and per-Key observations, and paginate New API model imports. Background observations no longer invalidate unrelated configuration editors.
- Isolate billing snapshots by account binding, serialize local configuration writes, and apply personal-credit changes atomically.
- Unify individual-model editing for built-in and HTTP suppliers, including public aliases, protocol choices and routing switches. Built-in adapters retain their fixed endpoints and authentication.
- Publish known model limits, modalities and reasoning tiers to DSH. Add per-model capability declarations and cached models.dev fallback data; derive image input support from metadata instead of model names.
- Add runtime log filtering and opt-in credential-redacted request capture. Development mode enables capture by default; captured files still contain conversation content. See [request debugging](../maintainer/development.md#request-debugging-and-log-levels).

## Verification

The local Gateway Lab passed all 98 scenarios with zero remote calls and verified process/port cleanup. Subsequent CI lint corrections preserve the tested routing and billing behavior.

Local Windows release preflight and the production web build passed with Node.js 22.23.3; the CLI build also passed. DSH 0.1.7-rc.2 passed isolated plugin installation, credential import, a loopback streaming call, context and reasoning-tier mapping, and Web installation/removal with the original bundle list preserved. These tests used temporary profiles.

The final commit must pass main Quality before tagging. The release workflow verifies all three platform packages and updater signatures before publication; the separate container workflow verifies both architectures and anonymous pulls. No real supplier calls or interactive macOS/Linux desktop sessions were used for this preparation. Windows installers have no Authenticode signature; macOS apps use ad-hoc signing and are not notarized.
