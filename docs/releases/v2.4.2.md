# v2.4.2

[简体中文](v2.4.2.zh-CN.md)

A main-only patch candidate built from `7981406ad532d2f730b062c0d5900242e3d5f658`. It includes the changes already merged into main after v2.4.1 and the quality repairs described below. No unmerged feature branch is included.

## Changes

- Fix Command Code GOAT transient/unknown 429 handling: without a valid upstream deadline, retry another eligible account for this request without writing account cooldown or replacing an otherwise available global sticky target. Valid `Retry-After` or recognized plan-window reset times still govern real cooldowns ([#66](https://github.com/klarkxy/open-console-gateway/pull/66)).
- Recognize GOAT's explicit insufficient-credit HTTP 400 and continue to another eligible account instead of immediately returning that account rejection. Unknown recovery remains unknown; no cooldown or authentication failure is invented ([#65](https://github.com/klarkxy/open-console-gateway/pull/65)).
- Preserve keyless public Go catalog discovery and dynamically discovered Go model aliases. Public catalog regression tests now verify a single GET with no Authorization, API key, cookie or request body.
- Preserve explicit protocol enablement: an unknown model ID does not establish Chat support. Regression coverage includes Auto/ForceOn/ForceOff transitions, safe reset behavior when official documentation is unavailable, and removal of an explicitly enabled proxy route.
- Repair stale model-list and protocol fixtures to cover the current runtime catalog. A missing price entry must not hide an otherwise enabled Go model; disabled protocols must not become routable.
- Fix the release-blocking unused import and slice-membership lint findings. Include the existing tooling regression suite in the default test command.
- Synchronize package, Rust, Tauri and Compose versions at 2.4.2. Cargo regenerated the workspace lockfile; verification confirmed that external dependencies did not change.

## GOAT recovery scope

As checked on 2026-09-19, the latest public stable release is still v2.4.1. That binary does not include #65 or #66. Both source fixes are included in this 2.4.2 candidate; a successful candidate build does not make them available through the stable updater. The September 19 reproduction in [#62](https://github.com/klarkxy/open-console-gateway/issues/62#issuecomment-5739916214) was made on v2.4.1, not on the fixed source or this candidate.

With the fixes, a transient 429 on healthy sticky account A followed by an explicit credit 400 on H can continue to a third eligible account for the same request. Neither error, without an upstream deadline, makes A or H persistently unavailable. A remains the sticky target when it was otherwise available. If H itself is already the sticky target, a new request can still try H before falling back; repeated failed-attempt latency is not solved by request-local fallback. If no eligible account succeeds, the request still fails.

Cross-request waiting/reprobe for a proven insufficient-credit account with unknown recovery is tracked separately in [#71](https://github.com/klarkxy/open-console-gateway/issues/71). It is not implemented by #65, #66 or this candidate. A future local probe schedule must not be represented as an upstream quota reset, and must not turn unrelated transient 429s into account cooldowns.

## Release boundary

These are manually dispatched candidates, not a published production release. They do not contain production updater signatures. No v2.4.2 tag, GitHub Release, stable update-channel change or GHCR publication was performed by preparation. The normal annotated-tag release remains responsible for those operations and its signing and publication gates remain unchanged.

Real-client protocol checks and manual desktop use have not been performed. Automated smoke results must not be presented as manual validation. Compose's 2.4.2 image references become usable only after the corresponding container release is published.
