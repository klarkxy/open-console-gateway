# v2.6.0

[简体中文](https://github.com/klarkxy/open-console-gateway/blob/v2.6.0/docs/releases/v2.6.0.zh-CN.md)

## Upgrade

Stop processes using the data directory and back up the whole directory before upgrading. The database migrates from schema v62 to v63; older binaries cannot open the upgraded database. Rollback requires the pre-upgrade backup.

The desktop app synchronizes its bundled Codex skill on the first launch after installation or upgrade. The native release CLI does the same when `serve` starts; `ocg-manager-cli skill sync` runs it explicitly. The skill is written to the current user's `~/.agents/skills/ocg-manager`. A previous OCG-managed copy is backed up before replacement; an unowned skill or a locally edited copy of the current bundle is left alone. Containers cannot install a skill on the host.

## Changes

- Configure saved per-model protocol routes and explicit endpoint grants. Provider catalogs and Account controls now expose those choices without inferring a protocol from the model name. Kimi rolling model IDs retain their exact spelling.
- Keep routing and probes aligned with saved HTTP routes. Correct grant selection, site subpaths, quota classification, request attribution, and late account refreshes that could otherwise show stale or misleading state. Platform-linked fallback attempts retain native price attribution only when the sent endpoint is still a saved route.
- Bundle an agent skill for local download, installation, deployment, configuration, upgrade, and troubleshooting. The installed CLI's `--help` remains the authority for command syntax and supported scope. Secret entry stays in the user's local dashboard or client; the agent must not request a Key in chat.
- Hide the Gateway Key in ordinary CLI `status` and `serve` output. `status --show-key` displays it only when explicitly requested in a private terminal.
- Update the project license to SATA 2.1. Starring and thanking the author are invitations, not conditions of use.

## Verification

Local Windows validation passed 768 frontend tests and 2,230 Rust workspace tests (nine opt-in tests ignored). The tooling suite, design lint, V3/V4 contract checks, typecheck, web build, and unsigned release preflight passed. The local Gateway Lab suite passed with `remoteCalls=0` and process/port cleanup verified.

An unsigned Windows installer and native CLI ZIP were built. Both files matched `SHA256SUMS`. The extracted CLI served its dashboard, hid the Gateway Key in ordinary `status` and `serve` output, installed the bundled skill into an isolated user home on first start, and reported the next sync as up to date. The production tag workflow will separately build and verify signed updater payloads across Windows, macOS, and Linux before publication.

Real provider requests, interactive desktop installation and upgrade, desktop first-launch skill sync, SmartScreen, macOS/Linux desktop use, browser-profile persistence, and client Key clipboard contents were not exercised locally. No real credentials entered the agent's tools or test artifacts.

Updater payloads carry Tauri minisign signatures. Windows installers have no Authenticode signature; macOS apps use ad-hoc signing and are not notarized.
