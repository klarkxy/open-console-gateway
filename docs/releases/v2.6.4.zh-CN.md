# v2.6.4

[English](v2.6.4.md)

## 升级

升级前停止所有使用数据目录的进程，并备份整个目录。数据库 v64 会在没有名称冲突时，将预设生成的 `<preset-id>/<upstream-id>` 公开模型名改为上游 ID 的最后一段。使用旧名称的客户端需要同步修改请求模型名。准确的上游 ID、手动命名的映射和历史日志保持不变。旧版程序无法打开 v64 数据库；回退需恢复升级前的完整目录。详见[迁移指南](../maintainer/storage-migration.zh-CN.md)。

更新 OCG 后，在 **应用 → DSH** 中重新安装或替换一次插件，再重新加载 DSH，才能使用本次模型元数据改动。

## 变更

- 账号和供应商的保存、删除操作在服务端确认后立即结束，相关列表在后台刷新。阻止迟到的观测结果恢复已删除账号，支持删除关联平台的本地 Key，以及删除空的可配置 HTTP 账号组。
- 账号刷新改为排队执行，区分平台与单个 Key 的观测范围，并分页导入 New API 模型。后台观测不再使无关的配置编辑失效。
- 按账号绑定隔离计费快照，串行提交本地配置写入，并原子应用个人积分变更。
- 统一内置供应商与 HTTP 供应商的单模型编辑，支持公开别名、协议选择和路由开关。内置适配器的端点与认证方式保持固定。
- 向 DSH 提供已知的模型容量、模态和推理档位。支持逐模型声明能力及 models.dev 本地缓存补充；图片输入能力由元数据决定，不再按模型名称推断。
- 增加运行日志筛选及可选的凭据脱敏请求记录。开发模式默认开启记录；文件仍含对话内容。详见[请求调试说明](../maintainer/development.zh-CN.md)。

## 验证

本地 Gateway Lab 的 98 个场景全部通过，远程调用为 0，测试进程和端口已确认清理。之后的 CI 静态检查修正保持已测路由和计费行为不变。

本地 Windows 发布预检及网页生产构建在 Node.js 22.23.3 下通过，CLI 构建也已通过。DSH 0.1.7-rc.2 通过隔离插件安装、凭据导入、回环流式调用、上下文与推理档位映射，以及 Web 安装和移除测试；原插件列表保留。测试均使用临时配置目录。

最终提交须先通过 main Quality，再打标签。发布流程在公开前验证三平台安装包和更新签名；独立容器流程验证两种架构及匿名拉取。本次准备未调用真实供应商，也未进行 macOS/Linux 桌面人工交互测试。Windows 安装程序没有 Authenticode 签名；macOS 应用使用 ad-hoc 签名，未公证。
