# v2.5.0

[简体中文](v2.5.0.zh-CN.md)

## Upgrade

Stop processes using the data directory and back up the whole directory before
upgrading. The database migrates to schema v62; older binaries cannot open the
upgraded database. Rollback requires the pre-upgrade backup.

The dashboard now uses `/dashboard/api/v4`. V3 returns HTTP 410; integrations
that call dashboard endpoints must migrate to V4. Inference endpoints and
existing client Keys remain unchanged. Portable backups export V10 and accept
V4–V10 imports.

## Changes

- Manage shared HTTP connection settings on Providers and independent Keys on
  Accounts. Multiple routing cards can use one supplier, allowing priorities
  such as A1 → B1 → A2 without duplicating its configuration.
  HTTP model names retain distinct spaces and separators when listed and routed.
- Explain saved routing choices from Aliases, including credential order,
  protocol selection and reasons an account is excluded.
- Persist confirmed quota exhaustion per Key and admit one real request when
  it becomes eligible to retry. Keep temporary endpoint restrictions and
  `Retry-After` separate from quota-reset evidence. All fallback attempts share
  one request budget.
  Catalog refreshes preserve already-observed shared Free-limit evidence.
- Show timed quota, official cash observations and personal credit estimates
  through the account billing view. Configurable HTTP accounts support
  per-model credit rates, monthly issuance, expiring top-ups and calibration.
  Estimates never disable routing. Platform-linked Keys retain their existing
  site billing views.
  Authenticated New API Key price refreshes do not need a site-wallet query.
- Preserve personal balances across rate edits and backups. Repeated stream
  completion cannot debit twice; rejected requests settle at zero, while
  missing usage or interrupted outcomes remain explicitly unknown.
- Keep active settlement records intact when another CLI command opens the
  same database. Reject late usage responses after logout, account changes or
  view disposal.
- Preserve the upstream failure and recovery fixes from
  [#73](https://github.com/klarkxy/open-console-gateway/pull/73), including GOAT
  credit rejection, scoped temporary waits and bounded stream retries before
  the first downstream output.

## Verification

Local validation on Windows 11 (build 26200) passed 700 frontend tests,
91 release-tooling tests and 58 Gateway Lab fixture tests, plus the web build.
The final core unit run passed 1,250 tests (seven opt-in tests skipped), with
focused integration coverage for routing, recovery, budgets, backups and V4
destinations. Two opt-in public pricing checks also passed.
Strict workspace lint, V3/V4 contract checks and the final CLI build passed.
The full local Gateway Lab run passed with zero remote calls and verified
process/port cleanup. One earlier cleanup exceeded its timeout; the process
and port were confirmed closed, then the complete run passed unchanged.

An isolated Windows dashboard session exercised account credit configuration,
top-ups, request logs and routing explanations. A simulated upstream request
confirmed the configured debit. Chrome's runtime version was not captured.
The release workflow reruns workspace tests, lint and API contracts, builds
all three platforms and verifies updater signatures before publication.

Real paid-provider requests, Key clipboard contents, interactive installation,
upgrade/uninstall and autostart, macOS/Linux desktop use, browser-profile
persistence, SmartScreen and real managed sign-up/payment flows are not part
of this local validation.

Updater payloads carry Tauri minisign signatures. Windows installers do not
have Authenticode signatures; macOS apps use ad-hoc signing and are not notarized.
