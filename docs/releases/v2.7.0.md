# v2.7.0

[简体中文](v2.7.0.zh-CN.md)

## Upgrade

No database migration. The schema stays at v64, and a v2.6.4 data directory opens directly. Back up the data directory before upgrading; rolling back to v2.6.4 means restoring that backup, since this version writes receipt and configuration files the older one does not read.

A data directory written by a newer build is refused at startup, with a signed update offered from the existing release endpoint. This only triggers when the schema version is newer than this build.

## Changes

- Add BYOK client configuration for Codex, Kimi Code, MiniMax Code and ZCode. OCG writes its gateway address and a Key into each client's own configuration, merging the provider entry instead of replacing the file. Writes are atomic, reject symlinks, and roll back from a journal when a write is interrupted. Removing the client's configuration file leaves the entry configurable again.
- Persist whether a managed CPA was explicitly started or stopped, and restore the owned child process on startup only when it was left running. Updating an installation that predates this setting keeps it running across the next startup. The outbound proxy policy is applied to the managed CPA process through its configuration file.
- Report BYOK and CPA host operations through the console log sink, with credentials redacted.
- Block startup when the data directory schema is newer than the running build, and offer a standalone signed update.
- Align the alias page with the models a downstream client can actually route to.
- Reduce redundant dashboard loads and stabilize hot renders. Account plan and status filters stay in effect while the lists are memoized.
- Drop the legacy `open-console-gateway` provider route from the DSH plugin.
- Add a split development mode and forward extra Tauri CLI arguments.

## Verification

Focused checks on the release candidate: the `ocg-core` BYOK host and CPA runtime suites passed 150 tests with 1 ignored (the device-login smoke needs a live executable and network). The primary-key rotation was verified directly against the connection store: a logout landing while rotation is in flight no longer fetches plaintext, and a stale load cannot overwrite the rotated key.

The final commit must pass main Quality before tagging. The release workflow verifies all three platform packages and updater signatures before publication; the separate container workflow verifies both architectures and anonymous pulls. No real supplier calls or interactive macOS/Linux desktop sessions were used for this preparation. Windows installers have no Authenticode signature; macOS apps use ad-hoc signing and are not notarized.
