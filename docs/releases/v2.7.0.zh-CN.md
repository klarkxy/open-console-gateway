# v2.7.0

[English](v2.7.0.md)

## 升级

没有数据库迁移，schema 仍是 v64，v2.6.4 的数据目录可以直接打开。升级前请备份数据目录；回退到 v2.6.4 需要恢复该备份，因为本版本会写入旧版本不读取的回执和配置文件。

数据目录的 schema 版本高于当前程序时，启动会被拒绝，并从现有的发布端点提供经过签名的更新。只有 schema 版本更新时才会触发。

## 变更

- 新增 Codex、Kimi Code、MiniMax Code、ZCode 的 BYOK 客户端配置。OCG 把网关地址和 Key 写入各客户端自己的配置文件，只合并供应商条目，不覆盖整个文件。写入是原子的，会拒绝符号链接，中断时按日志回滚。客户端配置文件被删除后，条目可以重新配置。
- 记录托管 CPA 是被显式启动还是停止，只在上次保持运行时才在启动时恢复子进程。升级一个早于该设置的安装时，运行中的进程在下次启动后仍会恢复。出站代理策略通过配置文件应用到托管的 CPA 进程。
- BYOK 与 CPA 的宿主机操作写入控制台日志，凭据已脱敏。
- 数据目录的 schema 版本高于当前程序时拒绝启动，并提供独立的签名更新。
- 别名页与下游客户端实际可路由的模型对齐。
- 减少仪表盘的重复加载，稳定高频渲染。账号的方案和状态筛选在列表缓存后仍然生效。
- DSH 插件移除旧的 `open-console-gateway` 供应商路由。
- 新增分离的开发模式，并转发额外的 Tauri CLI 参数。

## 验证

候选版本的专项检查：`ocg-core` 的 BYOK 宿主机与 CPA 运行时测试通过 150 项，1 项忽略（设备登录冒烟需要可执行文件和网络）。主 Key 轮换直接在连接 store 上验证：轮换期间发生的注销不再拉取明文，更早发出的加载也不能覆盖轮换后的 Key。

最终提交须先通过 main Quality，再打标签。发布流程在公开前验证三平台安装包和更新签名；独立容器流程验证两种架构及匿名拉取。本次准备未调用真实供应商，也未进行 macOS/Linux 桌面人工交互测试。Windows 安装程序没有 Authenticode 签名；macOS 应用使用 ad-hoc 签名，未公证。
