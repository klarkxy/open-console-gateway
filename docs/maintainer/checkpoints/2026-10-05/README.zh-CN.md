# 检查点证据归档

先阅读[工作检查点](../../work-checkpoint-2026-10-05.zh-CN.md)。这里保存重装电脑前已选方案、源码复核和有限观察。旧的调度指令、施工任务及运行授权均属于已关闭的历史记录；归档不授权执行、读取凭据、发布，也不代表验收通过。

- `plans/`：已选实例映射契约、接口签名、方案适度性及原生验收计划。先补完部分 Rust 消费者，再编译。
- `reviews/`：回滚、夹具清理、保留恢复、原生 CLI 归档判定及 SDK 源码复核。READY 仅指对应源码检查点，不是运行通过。
- `native-critical/`：未编译的 SDK/host 测试补充及源码回执。两个 SDK 文件加入新的固定源码树 `sdk/cliproxy/auth`，host 文件加入隔离 host 模块，不能悄悄替换生产源码。
- `reports/`：主协调者 CPA 测试退出记录、G 失败/中断日志、恢复观察及源码/散列快照。不包含隔离数据库、凭据、二进制快照或完整依赖树。
- `MANIFEST.json`：归档文件 SHA-256。重用精确源码或结果前先校验。

通过已提交的构建脚本重新准备固定 CPA 源码，保留 host 模块到所选补丁树的既有 `replace` 关系。有缓存时使用离线依赖及本地模拟服务器；这些测试不涉及真实提供商或已安装配置。SDK 源码已复核的用例仍是 UNRUN，不因旧的 dispatch-guard 结果而改变。Linux/macOS 编译与原生运行分开记录。
