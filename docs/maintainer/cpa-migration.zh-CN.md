# CPA 路线的迁移边界

本页落实[只使用本地 CPA 的架构](../architecture.zh-CN.md)。OCG 拥有一个本地 CPA，不设立专用外部 CPA 产品模式，这是设计。命令是 `ocg`，包是 `ocg-cli`，默认数据根是 `~/.ocg3`。完整 CLI 验收尚未完成。本页不记录运行成功。

## 历史基线、保留源码与 CPA 入口

上一代在自己的网关内核里执行推理：选择、发送、协议转换、回退和普通退避都在那个内核里。该内核是这一代所替换的历史基线。它不是当前的公共转发路径。

树里仍有更早的执行代码和专用的远端 CPA 接入：`OCG_CPA_BASE_URL`、自有与 integration 之间的目标选择器、保存的基址加远端管理凭据、固定 Docker 源 `http://cpa:8317`、保留的单例账号，以及 `/external-integrations/cpa` 下的路由。这些保留源码不是公共推理路径，也不是回退。历史远端设置继续保存。不自动激活，也不删除。把它们迁到本地运行时是显式迁移。保留代码要等消费者迁完再移除。

`crates/ocg-core/src/gateway/handler.rs` 里的公共生成与计数处理函数通过 `cpa_ingress::forward_public` 转发。该入口是新源码。它尚未被验收。完整 CLI 验收，包括这一代的编译和运行，尚未完成。

产品目标是本 OCG 安装拥有的一个本地 CPA 进程。私有推理和管理都留在这个子进程上。没有外部 CPA 模式，没有目标选择器，没有远端管理凭据，也没有单独的远端就绪或目录合约。子进程不可用时，历史内核不是回退路径。受支持的自定义 HTTP 供应商仍是供应商能力，由本地 CPA 执行。取消远端 CPA 产品模式，不会让自定义 HTTP、密封供应商、OAuth 与导入、客户端 Key 或应用宿主一起退出。完整的无界面 CLI 是当前交付物。已接受的 GPUI/Ely GUI 继续推迟。操作命令见 [CLI 指南](../user/cli.zh-CN.md)。开发说明见[开发](development.zh-CN.md)。当前路由见[HTTP 合约](dashboard-api.zh-CN.md)。

这些 crate 的现有依赖图不是目标的永久边界。保留需要的产品、控制面、存储和安全代码，由自有本地 CPA 承担发送与执行。当前分支没有 Vue/Tauri workspace，也没有原生 GPUI GUI。桌面目标仍是共享控制操作的 GPUI/Ely 客户端。无界面 CLI 不依赖该 GUI，并且在无界面验收之前不开始 GUI。

## 代际分支

产品身份仍是 Open Console Gateway。`ocg3` 与 `open-console-gateway` 是这一棵项目树的两个代际分支，如同 Python 3 与 Python 2 是同一种语言的两代。本页属于 OCG3 这一代。自有本地 CPA 的设计不是对上一代的普通兼容补丁，也不是一个无关的新项目。这个分界的设计来源是[架构里的谱系一节](../architecture.zh-CN.md#产品谱系与代际分支)。

用户命令是 `ocg`（Windows 上为 `ocg.exe`，Linux 与 macOS 上为 `ocg`）。Rust 包是 `ocg-cli`，位于 `crates/ocg-cli`。包名不是第二条用户命令。没有名为 `ocg-manager-cli` 的别名可执行文件。历史上已发布的名称、包标识和备份格式标签仍是历史引用。[CLI 指南](../user/cli.zh-CN.md)描述该命令和 `~/.ocg3` 默认目录。

默认 CLI 数据根是 `~/.ocg3`。未显式指定目录的启动使用该根。它不打开、不复制、不移动、不删除、也不接管上一代的默认配置与数据，包括 `~/.ocg-mgr-cli`。显式 `--data-dir` 仍然支持，并按原有方式校验。把上一代文件带入新目录是单独的显式迁移。备份仍是操作者自己的副本。序列化标签和加密兼容性保持现有名称。

## 保留、替换与退出

| 内容 | 迁移处理 |
| --- | --- |
| 用户命令与默认数据根 | 命令是包 `ocg-cli` 的 `ocg`。默认根是 `~/.ocg3`。不自动复用 `~/.ocg-mgr-cli` 或其他上一代默认目录。显式 `--data-dir` 保留。旧文件只通过显式迁移搬动。备份保留 |
| CLI 操作、Key 管理、访问控制、CAS | 保留并接入同一控制服务；不允许客户端绕过 OCG 进入自有本地 CPA |
| Plan/供应商身份、凭据绑定、模型范围、别名和优先顺序 | 保留产品语义，为自有本地 CPA 生成路由配置；不在入口另选执行 Key |
| 精确额度与官方用量解析 | 保留可信来源适配，归一化范围与截止时间，并在自有本地 CPA 内部同步生效 |
| 供应商 HTTP、OAuth 刷新、协议转换、SSE 执行 | 执行移交自有本地 CPA；尚未具备的能力保持为明确的产品缺口 |
| 受支持的自定义 HTTP 供应商，以及其他真实的供应商或应用能力 | 保留。本地 CPA 执行自定义 HTTP。结束远端 CPA 产品模式，不会让这些能力或其 CLI 消费者退出 |
| 原 selector、forwarder、fallback、普通退避和通用规则恢复 | 新路径由自有本地 CPA 承担。旧内核不是回退。只有在消费者迁完之后，才删除过时实现与测试。这项删除尚未发生 |
| 本地估算、估价与积分结算 | 从执行准入与选择中移除；已有用户数据显式导出或保留，不因删代码直接删表，也不把估算当成权威额度 |
| 自有本地 CPA 的安装、认证文件和进程生命周期 | 必需的执行运行时。OCG 只管理自己拥有的子进程。私有推理和管理留在该子进程上 |
| 专用远端 CPA 产品模式 | 不属于目标。历史基址、管理密文、推理材料和目录行继续保存。不自动激活，也不删除。显式迁移是必需的，且尚未实现 |
| 其他客户端/应用接入与账号工具 | 按 CLI 可用性和消费者逐项保留或列明差异；不能由删除旧架构文档推断全部退休 |
| 原生 GPUI/Ely 桌面 GUI | 架构中已接受的未来设计；A 首页、C Plans、B 可选紧凑模式。推迟到无界面 CLI 验收之后。尚未实现 |
| WebUI、WebView 主界面、托盘、旧前端重构计划 | 不在本次确定的 GUI 范围内；现有已发布版本资料仅作历史资料 |

## 实施顺序

1. 把产品配置投影到这一个自有本地 CPA，包括公开模型、优先级、模型权限、代理和秘密归属。自有子进程可以运行之前，不要求先有远端 CPA 行或全局远端管理客户端。每项旧能力都映射到本地 CPA 的等价能力或显式缺口。受支持的自定义 HTTP 仍是这条路径上的供应商能力。
2. 通过现有 CLI 与控制操作，接入自有子进程的启动、配置应用、就绪、停止和失败状态。就绪指的是自有子进程。已保存的远端设置不能满足就绪。
3. 在该子进程内实现同步扩展：携带实际凭据身份，记录额度证据，并在下一次发送前决定继续或停止。SDK 或小补丁的承载选择留给实施。不把实验插件升级成产品框架。
4. 公共处理函数通过 `cpa_ingress` 转发客户端执行。保留 OCG 鉴权、公开模型发布、总期限与取消、记录关联和脱敏。选择与重试只有一个所有者。不可用就是不可用。旧内核不接过这个请求。该路径的验收属于尚未完成的完整 CLI 验收。
5. 把历史远端设置报告为需要显式迁移。在该迁移存在之前，这些设置保持存储、关闭和脱敏。本地路径接替受支持的消费者之后，再切断旧内核，并删除其过时代码、测试和只服务于旧内核的数据路径。这一顺序尚未完成。

迁移期间可以在分开的目录里比较。生产请求只执行一次，并且走自有本地 CPA。不对真实生成请求双发，也不把旧内核当作故障后的透明回退。

## 原生 GUI 工作

[架构](../architecture.zh-CN.md#9-原生桌面-gui)是 GUI 设计的唯一来源。布局 A、C、B 以及 GPUI 和 Ely 继续有效。GUI 工作推迟到无界面 CLI 验收实际达成之后。未来的客户端附着到本地 OCG 控制服务。它不增加外部 CPA 画面，也不取得数据库或本地 CPA 进程的所有权。迁移过程中复用已实现的控制操作，并把剩余目标缺口明确标出，不伪装成可用能力。GUI 的启动、授权、重连和完整共享备份恢复仍需要生命周期实现。原生平台样窗是以后的检查点。GUI 继续推迟。

## 兼容、安全与回滚

访问 Key、公开模型名称和 V4/CAS 控制面仍是兼容基线。用户命令是 `ocg`，默认数据根是 `~/.ocg3`，如 [CLI 指南](../user/cli.zh-CN.md)所述。合约变更同时更新 schema 与成对的用户指南。已存储的行和上一代配置目录留在原处，直到显式迁移搬动它们。

持久化身份、凭据与绑定、目录、访问权限、用户秘密和加密身份必须可恢复。历史远端 CPA 配置属于这份可恢复数据。要识别它，并报告需要显式迁移。不要自动激活：不要打开已保存的基址，不要因为该行或 `OCG_CPA_BASE_URL` 存在就对它发起管理，也不要把省略的目标当成可以使用远端路径的许可。升级时不要删除它。不要把它的秘密复制进自有原生凭据，或复制进本地子进程的管理秘密。不要在状态、日志或迁移报告里打印这些秘密。显式迁移本身是以后的操作者动作，这里没有实现。数据库和导入格式以实际迁移代码与 schema 为准，不能从过时文档的版本号推导支持范围。已有备份说明见[存储迁移](storage-migration.zh-CN.md)与[升级备份](../user/upgrade-backup.zh-CN.md)。

切换前保留兼容的配置与认证目录备份。上一代数据目录留在原处。回滚恢复对应版本的运行文件、配置、数据库和加密材料，不让旧二进制直接读取更高 schema。不把 CPA OAuth token 错交给 OCG 的旧刷新器。删除旧内核仅在新路径接替其受支持消费者之后发生。这项删除尚未发生。`ocg` 的二进制验收与其余 CLI 一起尚未完成。

旧架构的关键保证继续成立：鉴权与秘密脱敏、URL/代理边界、目录权限、并发配置一致性、凭据轮换的迟到结果隔离、quota 截止时间持久化、流式取消与未知结果不重放。保留的是保证，而非实现这些保证的所有旧状态机。

## 文档与实施完成的区别

架构写明一个自有本地 CPA 和 Open Console Gateway 的产品谱系。本页把历史内核、保留的旧源码和当前 CPA 入口分开。该入口是新源码，尚未被验收。源码已定义 `ocg` 命令、`ocg-cli` 包和 `~/.ocg3` 默认目录。二进制验收尚未完成。

完整 CLI 验收要求：自有本地 CPA 上有完整的无界面 `ocg` CLI，精确额度与选择性禁止重放同时生效，历史远端设置要么仍保持惰性、要么已经显式迁移，上一代数据在没有显式迁移时保持不动，备份与回滚可用，并且失去消费者的旧执行代码已经删除。本次检查点不是那项验收，也不是发布。它不记录运行成功。
